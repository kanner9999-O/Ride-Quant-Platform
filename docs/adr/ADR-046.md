`4d67a8c3008231406f2038394fba6a7e98075bf4`), [`module-registry.yaml`](../architecture/module-registry.yaml)
(blob `8535f92efeb76ffb226791d201dc0b3fb71f06c0`), and the deterministic Context core
(`python/context-aggregator/src/context_aggregator/selection.py`, blob

**1. Context reasons about a computation cursor but does not persist one.** `context.md` §8
defines Eligible Upstream Fact selection explicitly in terms of a cursor `R` (Phase 1 step 2:
"Recorded-time visibility — `U.recorded_time <= R`"); §14 states "input eligibility = hai điều
kiện ĐỘC LẬP... (a) role fact.recorded_time <= computation cursor"; §15 requires "historical
Backtest/Replay tại một recorded cursor MUỘN PHẢI reconstruct MỖI `MarketContextSnapshot` chỉ
dùng fact thỏa CẢ HAI điều kiện tại đúng computation cursor của CHÍNH fact đó" — i.e. every
individual snapshot fact has its *own* computation cursor, not a global run-level one. Yet
`context.md` §3's `MarketContextSnapshot` payload (fresh-read verbatim) has no
`computation_cursor`, `input_contract_ref`, `stream_registry_version`, `lifecycle_frontier`, or
`stream_positions` field — the concept the prose depends on is never durably recorded on the
fact it governs. `context.md` §4's `MarketContextFactInvalidated` payload has the same absence.

**2. `normalized_input_fact_refs` cannot substitute for a cursor.** §10's seven-ref array
proves exactly which evidence *won* §8's selection. It cannot prove: which other visible
candidates *lost* selection (Phase 1/2 survivors that were not chosen); which facts existed but
were not yet visible; the valid stream universe at evaluation time; per-stream frontier
positions; the lifecycle frontier; or the exact Input Contract version pinned. This ADR does
not infer `R` from selected refs or from `envelope.recorded_time` — both are confirmed
insufficient by direct inspection of §3/§10's own field list.

**3. Scalar `recorded_time` alone is an insufficient visibility test.** Chapter 8 §8.5 fixes
the canonical Replay Cursor as five required fields — `recorded_time`, `input_contract_ref`,
`stream_registry_version`, `lifecycle_frontier`, `stream_positions` (§8.5.1's cardinality
table) — precisely because, per §8.5's own stated rationale, "`recorded_time` một mình là
không đủ khi nhiều event cùng recorded_time" and stream-universe/frontier membership must be
independently provable. §8.3.4 confirms visibility further requires per-stream in-sequence
position (`E.sequence <= R.stream_positions[E.stream_id]`, same-stream only — §8.3.3 forbids
any cross-stream sequence comparison). A scalar `recorded_time` field on a Context fact would
answer only one of the three required legs.

**4. Context cannot durably pin a Context-scoped Input Contract today.** Authoring a
standalone Context Input Contract before this ADR's cursor-binding decision would leave that
contract with no durable reference point anywhere in the Context fact schema — no field exists
for a Context computation to cite which Input Contract instance it pinned. Input Contract
authoring is therefore downstream of, not prerequisite to, this decision (consistent with
[ADR-035](./ADR-035.md)'s identical ordering for Feature: the cursor-schema ADR precedes the
Input Contract instance it references).

**5. Context correction semantics have a confirmed temporal-supersession gap.** `context.md`
§4's `MarketContextFactInvalidated` invariants (fresh-read verbatim) state:

> "payload.affected_upstream_roles PHẢI không rỗng... VÀ mỗi phần tử PHẢI tương ứng một
> causation_refs entry là đúng loại authoritative correction event cho role đó:
> context_cutoff_source → CandleCorrected; structure → StructureFactInvalidated hoặc
> StructureRecomputed; volatility_regime/directional_persistence_regime →
> RegimeFactInvalidated; volatility_metric_feature/directional_persistence_metric_feature/
> distance_to_last_confirmed_swing_feature → FeatureFactInvalidated."

This invariant is closed and exhaustive: every currently-legal causation for an affected role
is a **correction/invalidation event of the previously-cited fact itself**. It has no
provision for the case where a role's stored winner was never invalidated, remains valid, but
a **different, later-visible authoritative fact** — one that did not exist or was not yet
visible at the original computation cursor — now wins §8's deterministic Phase-2 total order
for that same role at the same computation point. This is the exact `distance_to_last_
confirmed_swing` case [ADR-034](./ADR-034.md) (Approved) already authorized for Feature
(`eligible_swing_selection_superseded`) and [ADR-035](./ADR-035.md) (Approved) already built
the durable-cursor evidence prerequisite for — generalized here to Context's six non-Candle
analytical roles (Structure; volatility Regime; directional-persistence Regime;
volatility-metric Feature; directional-persistence-metric Feature; distance-to-last-confirmed-
swing Feature). Candle.md/structure.md/regime.md/feature.md's own T-vs-T+n discipline
(`recorded_time` independent of `effective_time`/`analysis_window`/`effective_window`) makes
this scenario structurally possible for every one of those roles, not merely hypothetical: a
Structure orientation-setting fact, a Regime classification, or a Feature computation can each
be *recorded* late (backfill, reprocessing, delayed analytical run) while its own effective/
analysis boundary is early enough to have been eligible for an old Context computation point
all along. Current Context invalidation semantics do not govern this class, and this ADR does
not assume it is equivalent to an upstream invalidation of the previously-cited fact — it is
not: the previously-cited fact can remain perfectly valid.

**6. Candle is structurally different and is not affected by this gap.** Each Context
computation invocation (`python/context-aggregator/src/context_aggregator/aggregation.py`'s
`target_computation_point_ref`, CONTEXT-CORE-A-MAJ-01, Review-A-validated) is bound to one
explicit Candle computation point/window; an unrelated later Candle window can never supersede
an older computation point (enforced in `select_candle`'s window-scoped lineage resolution).
Candle correction for the *same* computation point remains ordinary Candle correction lineage
(`candle-corrected` → `context_cutoff_source → CandleCorrected`, already representable in §4's
existing invariant). This ADR's temporal-supersession decision (§5 below) applies only to the
six non-Candle analytical roles and explicitly preserves the Candle distinction.

**Authority-neutral framing (`MAJ-02`) — this ADR does not resolve the `context.md`-vs-Chapter-7
Projection terminology tension, and does not turn Context into an authoritative domain-state
owner.** [Chapter 7 §7.4](../constitution/07-module-taxonomy.md) (Locked) fixes exactly what a

projection consumed by Decision/Risk/Execution "phải khai báo criticality và failure policy
tường minh... khi tính đúng đắn hoặc độ freshness của nó không xác định, consumer phải fail-safe
theo I-6. **Điều này không biến projection thành authoritative source.**" `module-registry.yaml`
currently pins `context-aggregator`'s `module_type: projection` and
`owns_authoritative_state: false`; `feature-context-architecture.md` §5.2/§13 (Package 1.3-B,
Consolidated Stable) already documents, and explicitly preserves unresolved, a terminology
tension between `context.md`'s own §2 envelope framing ("authoritative event record" — the
generic Chapter 8 §8.2 label every event in that section inherits, not a Context-specific
assertion) and the Projection/non-authoritative classification `module-registry.yaml` and
Chapter 7 pin. This ADR is **not authorized to silently resolve that preserved gap**, and does
not attempt to. Accordingly:

1. This ADR does **not** change `module_type: projection`, `owns_authoritative_state: false`,
   [Chapter 7 §7.4](../constitution/07-module-taxonomy.md), or the existing unresolved
   terminology tension in `context.md` — none of `module-registry.yaml`, `context.md`, or
   `feature-context-architecture.md` is edited by this transaction.
2. Adding a canonical `computation_cursor` gives the durable Context projection record
   (`MarketContextSnapshot`/`MarketContextFactInvalidated`) durable knowledge-boundary
   evidence — record-integrity (immutable, cursor-bounded, lineage-preserving, eligible per
   §8) — it does **not** make Context an authoritative source for Structure, Regime, Feature,
   Candle, Strategy, Decision, Risk, or any other business-domain concept. Throughout this ADR,
   Context's own output is referred to as the **Context projection record** — an eligible
   cursor-bounded projection record carrying durable replay evidence — never as "the
   authoritative Context event/fact," to avoid implying domain-state ownership this ADR does
   not grant and Chapter 7 §7.4 forbids.
3. Decision (or Risk) may depend on Context as a critical deterministic projection under
   Chapter 7 §7.4's own criticality clause, with fail-safe behavior when Context is
   unavailable or its freshness/correctness is uncertain (I-6); that dependency does **not**
   convert Context into authoritative domain ownership of anything it aggregates — the
   dependency relationship and the authority classification are two separate axes, and this
   ADR touches only the former (durable evidence a consumer could use to reason about
   freshness/boundary), never the latter.
4. This ADR does **not** resolve whether `context.md`'s own §2 legacy phrase "authoritative
   event record" should later be rewritten to a Projection-consistent term. That question is
   explicitly out of scope here, unless separately governed by its own bounded `context.md`
   amendment transaction (see Consequences).
5. Follow-on Context Event Contract/publication work (Consequences items 2–4) must preserve
   this identical authority boundary — no follow-on transaction may use this ADR as
   justification for reclassifying `context-aggregator` as authoritative, hybrid, or a
   `runtime_service`/`compute_engine` module type.

**Decision:**

**1. Canonical cursor — reuse Chapter 8, do not invent a local schema.** Context's
`computation_cursor` field, wherever it appears (below), is the canonical
[Chapter 8](../constitution/08-event-model.md) §8.5 Replay Cursor **verbatim** — not a
Context-local near-equivalent. `context.md` §20 already commits Context to "áp dụng, không
định nghĩa lại... ordering/replay cursor mechanics (Chapter 5/Chapter 8)"; a parallel schema
would violate that authority boundary Context itself already pins, exactly the reasoning
[ADR-035](./ADR-035.md) applied to Feature via the identical `feature.md` §18 clause and the
Chapter 8 §8.4 (`decision_context_cursor`) reuse precedent.

```yaml
computation_cursor:                       # value type = canonical replay_cursor, Chapter 8 §8.5.1
  recorded_time:                          # Required — knowledge boundary
  input_contract_ref:                     # Required — {contract_id, contract_version},
                                           #   the Context-scoped Input Contract instance
                                           #   this computation pinned (Chapter 8 §8.3.4)
  stream_registry_version:                # Required — must match input_contract_ref's
                                           #   pinned registry version (§8.5)
  lifecycle_frontier:                     # Required — {stream_id, position: {kind, sequence}}
                                           #   on the canonical Lifecycle Stream (§8.3.5)
  stream_positions:                       # Required — map <stream_id> -> <sequence>,
                                           #   cardinality = exactly included_streams of the
                                           #   pinned Input Contract, valid at lifecycle_frontier
                                           #   — never a fixed count, never open-ended, never a
                                           #   cross-stream sequence (ADR-009's no-global-order)
```

**2. `computation_cursor` on `MarketContextSnapshot` — every fact pins its own boundary.**
Every `MarketContextSnapshot`, original or correction replacement alike, carries its own
required `computation_cursor` — the exact knowledge boundary under which §8's Eligible Upstream
Fact selection was evaluated to produce *that* fact. A replacement snapshot does **not** inherit
or copy the fact it supersedes' cursor; it pins its own actual re-evaluation boundary,
independent of `supersedes_fact_ref`'s target. This mirrors §15's own already-Locked prose
("mỗi fact" reconstructed "tại đúng computation cursor của CHÍNH fact đó") and
[ADR-035](./ADR-035.md)'s identical rule for `FeatureComputed`.

**3. `computation_cursor` on `MarketContextFactInvalidated`.** Every
`MarketContextFactInvalidated` also carries its own required `computation_cursor` — the
`R_later` boundary at which Ride proves the invalidated snapshot `C` is no longer the
CURRENT-VALID lineage-head result for its computation point (`MIN-01` — this is a later
knowledge-boundary transition, never a rewrite of `C`'s own historical correctness; see the
bitemporal clarification below Decision item 8). This is durable evidence distinct from: `C`'s
own `R_original` (a different fact's field, proving what `C` itself could see, not what
triggered its invalidation); `envelope.recorded_time` (append time — a different axis, per
`context.md` §14's explicit prohibition on substituting it for cursor semantics, carried
forward from `feature.md` §12/[ADR-034](./ADR-034.md)'s identical prohibition); and the
eventual replacement's own `computation_cursor` (a third, independent fact's boundary, per
Decision item 2 above). Fresh authority check performed: no existing mechanism —
`normalized_input_fact_refs`, `causation_refs`, `envelope.recorded_time`, or any current
Chapter-8/context.md field — durably proves `R_later` (see Ground-truth items 1–3 above);
this ADR therefore does not STOP on this point and proceeds with the invalidation cursor,
consistent with [ADR-035](./ADR-035.md)'s identical conclusion for `FeatureFactInvalidated`.

**4. Full visibility predicate — apply Chapter 8, do not redefine it.** An upstream event `E`
is visible at Context `computation_cursor R` **if and only if all of the following hold**
(identical in structure to [ADR-035](./ADR-035.md)'s Feature-scoped predicate, applied here to
Context):

```text
1. E.stream_id is in R's valid stream universe — E.stream_id is one of
   R.input_contract_ref's included_streams, and that stream's inclusion is valid at
   R.lifecycle_frontier (Chapter 8 §8.3.5 Retained-in-Universe semantics);
2. E.sequence <= R.stream_positions[E.stream_id] — an IN-STREAM position boundary only;
   NO cross-stream sequence comparison is ever performed (Chapter 8 §8.3.3);
3. E.recorded_time <= R.recorded_time (Chapter 5 §5.3's recorded-time boundary).
```

Any leg failing makes `E` not visible at `R`. Context still **independently** applies its own
effective-time cutoff (`context.md` §8 Phase 1 step 3, §14(b)) on top of this — visibility and
effective-time eligibility remain two separate, both-required conditions, exactly as `context.md`
§14 already states ("(a) một mình KHÔNG đủ"); this ADR does not collapse them.

**5. Temporal eligible-winner supersession — a role-resolution delta, bounded to the six
non-Candle analytical roles (`MAJ-03`).** For a stored Context projection record `C`, evaluated
at `computation_cursor R_original`, a later `computation_cursor R_later` **requires invalidation
of `C`** when, for at least one of Structure / volatility Regime / directional-persistence
Regime / volatility-metric Feature / directional-persistence-metric Feature /
distance-to-last-confirmed-swing Feature, exact `context.md` §8 re-evaluation of that SAME
Context computation point / SAME Context Definition under CURRENT authority establishes a
**role-resolution delta**:

```text
1. the role resolved to old ref A at R_original (C's currently-cited ref for that role);
2. one or more relevant upstream records/events needed to establish the role's state at
   R_later were NOT visible (full predicate, item 4) at R_original;
3. those exact records/events ARE fully visible (full predicate, item 4) at R_later;
4. effective-time eligibility (context.md §8 step 3) and producer-domain correction-lineage
   semantics already fixed in structure.md/regime.md/feature.md (never invented or redefined
   by this ADR) are applied exactly, using ONLY those authorities' own existing rules;
5. exact context.md §8 selection at R_later, for the SAME computation point and SAME Context
   Definition, yields either a DIFFERENT winning role ref for that role than A, OR causes
   that role to become missing/pending (§9) at R_later;
6. C therefore ceases to be the CURRENT-VALID lineage head/result for that computation point
   at R_later (see MIN-01 bitemporal clarification below — this does not rewrite C's own
   historical correctness at R_original).
```

The previously-selected role ref `A` is **not** required to have been itself invalidated — this
is a temporal winner-change condition, structurally distinct from repaint (§15's "KHÔNG BAO GIỜ
bị ghi đè tại chỗ" is unaffected: `C` is never mutated, only invalidated-and-replaced,
append-only). This generalizes [ADR-034](./ADR-034.md)'s `eligible_swing_selection_superseded`
condition (a)–(d) from Feature's single Eligible-Swing role to Context's six analytical roles,
preserving the identical condition-2-is-load-bearing distinction: a candidate that was
**already** visible at `R_original` but not selected is a computation *defect* in the original
fact (§8's algorithm not correctly applied), never this temporal-supersession cause — that
distinction is preserved unchanged here. Unlike v0.1's single-newly-visible-candidate framing,
step 2 above explicitly allows the delta to be established by a SET of one or more records
(Decision item 7's cause-ref set, below) — a single new record is the common case, but a
compound transition (e.g. a later-visible successor that is itself subsequently invalidated,
requiring both records as proof) is equally representable.

**6. Preserve direct upstream correction flow — integrate, do not replace.** Existing direct
correction/invalidation cases remain valid and unmodified by this decision: `CandleCorrected`
for the exact computation point (Candle role, item 6 of Context above); `StructureFactInvalidated`
/ `StructureRecomputed`; `RegimeFactInvalidated`/replacement; `FeatureFactInvalidated`/replacement.
The temporal-supersession condition (item 5) is an **additional** trigger for
`MarketContextFactInvalidated`, not a replacement of these.

**7. Invalidation representation — minimal change, per-role cause-ref SET, not one ref
(`MAJ-03`).** `context.md` §4's `affected_upstream_roles` array and `causation_refs` (a single
flat, canonical, deduplicated event-reference set — never a second, competing role-mapping
structure) are preserved. The change this ADR proposes to a follow-on `context.md` amendment
(not made here): for each role listed in `affected_upstream_roles`, its cause is no longer
assumed to be exactly one `causation_refs` entry — it is the **minimal complete deterministic
evidence set** required to prove that role's resolution delta at `R_later` (Decision item 5),
containing **one or more** exact direct upstream event refs, never an unrelated ref, never a
duplicate. Each entry is either (a) a correction/invalidation event that makes the stored role
ref invalid or missing (the six existing mappings, ground-truth item 5, unchanged — e.g.
`StructureFactInvalidated`), or (b) the later-visible authoritative fact itself (a plain
`structure-recomputed`/`break-of-structure-detected`/`change-of-character-detected`/
`regime-classified`/`feature-computed` event) that becomes the new §8 winner, or (c), when the
delta is compound, **both** a later-visible successor and that successor's own subsequent
invalidation (e.g. `{B, I_B}` — a `regime-classified` fact `B` plus the `RegimeFactInvalidated`
that later invalidates `B`, when the role resolves missing/pending because `B` itself did not
survive, per Ground-truth's compound example). **Role attribution remains fully deterministic
without a new schema field:** each referenced event's own governed type + role discriminant
(`regime_dimension`/`feature_type`, where applicable) + its target/ref relationship
(`invalidated_fact_ref`/`supersedes_fact_ref`, when present) unambiguously identifies which
role and which branch it belongs to — attribution is derived from these relationships, never
from `causation_refs`' list order. When two or more roles are affected independently in the
same `MarketContextFactInvalidated`, each role's cause set is resolved independently against
Decision item 5, and all resulting refs across all affected roles are unioned and deduplicated
into the one flat `causation_refs` array — `invalidated_fact_ref` remains separately required
exactly as existing Context invalidation semantics already require, unaffected. This satisfies
the existing "dedup cascade" principle §4 already cites from `structure.md` §10: one
`MarketContextFactInvalidated` per affected fact, listing every affected role and its complete
exact cause set, regardless of which branch (a)/(b)/(c) applies to each role independently.
Deterministic role→cause attribution is achievable entirely within the existing
`affected_upstream_roles` + flat `causation_refs` structure — no new field is required, and
this ADR does not introduce one.

**8. Re-evaluation result and replacement-cursor relation (`MAJ-04`).** At `R_later`, if
invalidation is triggered (item 5 or item 6): if any required role is missing/pending at
`R_later`, `C` is invalidated but **no** replacement is emitted until §9 permits a complete
snapshot; never stale-fallback to `C`; never fall back to an older Context window as a
substitute for the affected computation point. If all seven roles resolve, exactly one
replacement Context projection record is permitted for the SAME `(context_subject_id,
effective_window)` lineage, under exactly one of two legal cases — **never a third, implicit
case**:

```text
Case A — SAME re-evaluation boundary:
  replacement.computation_cursor == invalidation.computation_cursor == R_later
  The replacement's role refs/values MUST be exactly the §8 result already established
  by the R_later re-evaluation that triggered the invalidation — no separate recomputation
  is performed or permitted; reusing that exact result is correct precisely because no
  cursor advance occurred between invalidation and replacement.

Case B — LATER replacement boundary (no replacement at R_later, or publication/
re-evaluation genuinely occurs later):
  R_replacement != R_later
  The system MUST independently re-run exact context.md §8 selection at R_replacement —
  never reuse the R_later winner set under a different cursor. Role refs/values/
  normalized_input_fact_refs MUST reflect R_replacement, not stale cached R_later
  selection; any additional knowledge visible by R_replacement MUST be honored. The
  replacement still supersedes the invalidated lineage head and remains in the SAME
  (context_subject_id, effective_window) lineage, per existing Context correction rules
  (Decision item 2 — computation_cursor is never inherited, independent of which case
  applies).
```

This distinction is required even when all seven roles were already complete at `R_later` —
a successful `R_later` re-evaluation is proof that a replacement COULD have been produced at
that exact boundary; it is never proof that the SAME winner set remains correct at any later
boundary a genuine replacement actually publishes under. An implementation MUST record which
case applied (trivially derivable by comparing `invalidation.computation_cursor` and
`replacement.computation_cursor`, both already required fields) — no separate field is
introduced for this; the comparison is fully derivable from Decision items 2/3 alone.

**Bitemporal clarification (`MIN-01`) — historical truth vs. later current validity.** `C`
remains **immutable and historically correct** as the Context projection result genuinely
produced under `computation_cursor R_original` — temporal invalidation never rewrites that
historical fact, and never claims `C`'s own original evaluation was wrong. What changes at
`R_later` is only that `C` is no longer the **current-valid lineage head/result** for its
computation point — a later-knowledge-boundary transition, recorded exactly like every other
Context correction (append-only, §15's no-repaint invariant unaffected). Replay behavior is
unaffected and already correct under existing Context semantics: replay at a cursor before the
invalidation's own `recorded_time` still observes `C` as valid (§14's anti-look-ahead rule,
unaffected); replay at a cursor at or after the invalidation observes the invalidation, and the
replacement or `PENDING_CORRECTION` state as appropriate (§13, unaffected). This ADR changes
which durable evidence justifies a temporal invalidation (Decision item 5) — it does not alter
`context.md`'s existing no-repaint or bitemporal-truth invariants in any way.

**9. Context Input Contract binding — requirement only, not authored here.** This ADR
establishes only that a `MarketContextSnapshot`'s `computation_cursor.input_contract_ref` must
pin exactly one Context-scoped Input Contract instance under Chapter 8 §8.3.4. The expected
included-stream universe is derivable from existing authority — `market-data-ingestion-candle`,
`structure-engine-structure`, `raw-regime-engine-regime`, `feature-engine-feature` (fresh-read
from `stream-registry.yaml`'s current seven streams, matching `context.md` §16's exact
non-Swing, non-current-view input-event list) — no direct Swing stream is added; Context does
not consume Swing directly (`context.md` §16 explicit exclusion, unaffected). This ADR does
**not** author, publish, or activate that Input Contract artifact; that is deferred to a
separate, bounded follow-on transaction, the identical ordering [ADR-035](./ADR-035.md)
established for Feature.

**10. Fail-closed until referenced artifacts resolve.** Until all referenced artifacts
genuinely resolve — a published Context-scoped Input Contract, its exact version snapshot per
[ADR-041](./ADR-041.md), the pinned Stream Registry version, and the required upstream Event
Contract dependency authority — publication of a durable Context projection record under this
mechanism must fail closed. No process-local/in-memory value may substitute as durable replay
evidence (the identical fail-closed posture [ADR-034](./ADR-034.md)/[ADR-035](./ADR-035.md)
already established for Feature's analogous evidence prerequisite). Concretely: this ADR
authorizes the **schema** now; no Context projection record may **claim** `computation_cursor`
as durable evidence until the referenced Input Contract/Stream Registry artifacts it names are
genuinely persistently resolvable (§8.1.1's five conditions). This fail-closed rule concerns
evidence durability only — it does not itself grant, and must not be read as granting, any
authoritative-domain-state status (`MAJ-02` framing, above).

**11. No global total order.** Nothing in this decision creates ordering between streams.
Chapter 8's `P_global = P_stream ∪ P_causation` and the pinned Input Contract's deterministic
topological merge policy (§8.3.4) remain fully controlling. Raw `sequence` is never compared
across different stream identities — visibility predicate leg 2 (Decision item 4) is explicitly
same-stream-only, and the deterministic Context core's own existing total-order tie-break
(`python/context-aggregator/src/context_aggregator/selection.py::_compare_total_order`) already
enforces this same-stream-only discipline and is unaffected by this ADR.

**Alternatives considered:**

**A. Canonical Chapter-8 Replay Cursor on Snapshot + Invalidation, plus governed temporal
re-evaluation semantics (chosen).** Reuses already-Locked, already-owned mechanics exactly per
Chapter 8 §8.4's own reuse precedent and `context.md` §20's own "áp dụng, không định nghĩa lại"
boundary; the only alternative that durably proves both `R_original` and `R_later` from
evidence attached to the exact facts that need it, independent of process memory, execution
mode, or restart; the only alternative that closes the confirmed §4 causation-mapping gap
(Ground-truth item 5) without inventing a new authority.

**B. Cursor on Snapshot only, no durable invalidation cursor.** Cannot deterministically prove
`R_later`. `C`'s own `computation_cursor` proves only `R_original` — what `C` itself could see —
never the later boundary at which a different fact became visible/winning. Without a durable
`R_later`, condition 3 of Decision item 5 (visibility at `R_later`) would have to be inferred
from the replacement snapshot's own cursor instead — but the replacement does not exist yet at
invalidation time when the re-evaluation determines missing/pending (Decision item 8's
missing/pending branch), so no fact would carry `R_later` in that case at all. Rejected for the
identical reason
[ADR-035](./ADR-035.md) required `computation_cursor` on `FeatureFactInvalidated`, not only
`FeatureComputed`.

**C. Derive cursor from envelope `recorded_time` + selected input refs.** Rejected — confirmed
insufficient by Ground-truth items 1–2: does not prove the valid stream universe, per-stream
frontier positions, the lifecycle frontier, or which visible-but-unselected candidates existed
at evaluation time; `recorded_time` is append time, a distinct axis from evaluation-boundary
time (`context.md` §14, `feature.md` §12/[ADR-034](./ADR-034.md)'s identical prohibition).

**D. Store cursor only in process memory / a run manifest, not bound to each Context fact.**
Rejected — not durable, not restart-survivable, not independently reconstructable by a second
process or a different execution mode (Live/Backtest/Paper/Replay must each establish the
identical eligibility from identical durable evidence per `context.md` §15/§19 mode parity);
no already-authoritative per-fact binding mechanism exists that this alternative could rely on
instead — the deterministic Context core's own `aggregate_context_candidate` (Review-A-validated,
CONTEXT-CORE-REVIEW-A-DTR-001) is explicitly a process-local, non-durable computation, exactly
the gap this ADR closes.

**E. Create a Context-local cursor schema, deliberately distinct from Chapter 8's canonical
`replay_cursor`.** Rejected — Chapter 8 already owns canonical Replay Cursor representation in
full (§8.5); a parallel near-equivalent schema recreates the identical concept under a second,
competing authority, directly contradicting `context.md` §20's explicit "ordering/replay cursor
mechanics (Chapter 5/Chapter 8)" deferral and I-12's one-concept-one-authoritative-source
discipline — the identical rejection [ADR-035](./ADR-035.md) reached for Feature after its own
v0.1 made exactly this mistake (`P3-ADR035-A-MAJ-01`).

No materially distinct sixth alternative was identified beyond A–E; alternatives are not
padded to increase count.
