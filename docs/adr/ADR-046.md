[`context.md`](../domain/context.md) (blob `f9274d5749768151748b9dfa2713118a4fd77791`),
[Chapter 8](../constitution/08-event-model.md) (blob `4a27db556e6ee8f9b7ac085194a10c63677b035f`),
[`stream-registry.yaml`](../architecture/stream-registry.yaml) (blob
`4d67a8c3008231406f2038394fba6a7e98075bf4`), [`module-registry.yaml`](../architecture/module-registry.yaml)
(blob `8535f92efeb76ffb226791d201dc0b3fb71f06c0`), and the deterministic Context core
(`python/context-aggregator/src/context_aggregator/selection.py`, blob
`0a0a5cb62114163ddf6b54153a62c17a1c00dddd`), at repository boundary
`442df64a3fcd2216c95cfc58129332ffbb42bedf`:**

**1. Context reasons about a computation cursor but does not persist one.** `context.md` §8
defines Eligible Upstream Fact selection explicitly in terms of a cursor `R` (Phase 1 step 2:
"Recorded-time visibility — `U.recorded_time <= R`"); §14 states "input eligibility = hai điều
kiện ĐỘC LẬP... (a) role fact.recorded_time <= computation cursor"; §15 requires "historical
Backtest/Replay tại một recorded cursor MUỘN PHẢI reconstruct MỖI `MarketContextSnapshot` chỉ
dùng fact thỏa CẢ HAI điều kiện tại đúng computation cursor của CHÍNH fact đó" — i.e. every
individual snapshot fact has its *own* computation cursor, not a global run-level one. Yet
`context.md` §3's `MarketContextSnapshot` payload (fresh-read verbatim) has no
`computation_cursor`, `input_contract_ref`, `stream_registry_version`, `lifecycle_frontier`, or
`stream_positions` field — the concept the prose depends on is never durably recorded on the
fact it governs. `context.md` §4's `MarketContextFactInvalidated` payload has the same absence.

**2. `normalized_input_fact_refs` cannot substitute for a cursor.** §10's seven-ref array
proves exactly which evidence *won* §8's selection. It cannot prove: which other visible
candidates *lost* selection (Phase 1/2 survivors that were not chosen); which facts existed but
were not yet visible; the valid stream universe at evaluation time; per-stream frontier
positions; the lifecycle frontier; or the exact Input Contract version pinned. This ADR does
not infer `R` from selected refs or from `envelope.recorded_time` — both are confirmed
insufficient by direct inspection of §3/§10's own field list.

**3. Scalar `recorded_time` alone is an insufficient visibility test.** Chapter 8 §8.5 fixes
the canonical Replay Cursor as five required fields — `recorded_time`, `input_contract_ref`,
`stream_registry_version`, `lifecycle_frontier`, `stream_positions` (§8.5.1's cardinality
table) — precisely because, per §8.5's own stated rationale, "`recorded_time` một mình là
không đủ khi nhiều event cùng recorded_time" and stream-universe/frontier membership must be
independently provable. §8.3.4 confirms visibility further requires per-stream in-sequence
position (`E.sequence <= R.stream_positions[E.stream_id]`, same-stream only — §8.3.3 forbids
any cross-stream sequence comparison). A scalar `recorded_time` field on a Context fact would
answer only one of the three required legs.

**4. Context cannot durably pin a Context-scoped Input Contract today.** Authoring a
standalone Context Input Contract before this ADR's cursor-binding decision would leave that
contract with no durable reference point anywhere in the Context fact schema — no field exists
for a Context computation to cite which Input Contract instance it pinned. Input Contract
authoring is therefore downstream of, not prerequisite to, this decision (consistent with
[ADR-035](./ADR-035.md)'s identical ordering for Feature: the cursor-schema ADR precedes the
Input Contract instance it references).

**5. Context correction semantics have a confirmed temporal-supersession gap.** `context.md`
§4's `MarketContextFactInvalidated` invariants (fresh-read verbatim) state:

> "payload.affected_upstream_roles PHẢI không rỗng... VÀ mỗi phần tử PHẢI tương ứng một
> causation_refs entry là đúng loại authoritative correction event cho role đó:
> context_cutoff_source → CandleCorrected; structure → StructureFactInvalidated hoặc
> StructureRecomputed; volatility_regime/directional_persistence_regime →
> RegimeFactInvalidated; volatility_metric_feature/directional_persistence_metric_feature/
> distance_to_last_confirmed_swing_feature → FeatureFactInvalidated."

This invariant is closed and exhaustive: every currently-legal causation for an affected role
is a **correction/invalidation event of the previously-cited fact itself**. It has no
provision for the case where a role's stored winner was never invalidated, remains valid, but
a **different, later-visible authoritative fact** — one that did not exist or was not yet
visible at the original computation cursor — now wins §8's deterministic Phase-2 total order
for that same role at the same computation point. This is the exact `distance_to_last_
confirmed_swing` case [ADR-034](./ADR-034.md) (Approved) already authorized for Feature
(`eligible_swing_selection_superseded`) and [ADR-035](./ADR-035.md) (Approved) already built
the durable-cursor evidence prerequisite for — generalized here to Context's six non-Candle
analytical roles (Structure; volatility Regime; directional-persistence Regime;
volatility-metric Feature; directional-persistence-metric Feature; distance-to-last-confirmed-
swing Feature). Candle.md/structure.md/regime.md/feature.md's own T-vs-T+n discipline
(`recorded_time` independent of `effective_time`/`analysis_window`/`effective_window`) makes
this scenario structurally possible for every one of those roles, not merely hypothetical: a
Structure orientation-setting fact, a Regime classification, or a Feature computation can each
be *recorded* late (backfill, reprocessing, delayed analytical run) while its own effective/
analysis boundary is early enough to have been eligible for an old Context computation point
all along. Current Context invalidation semantics do not govern this class, and this ADR does
not assume it is equivalent to an upstream invalidation of the previously-cited fact — it is
not: the previously-cited fact can remain perfectly valid.

**6. Candle is structurally different and is not affected by this gap.** Each Context
computation invocation (`python/context-aggregator/src/context_aggregator/aggregation.py`'s
`target_computation_point_ref`, CONTEXT-CORE-A-MAJ-01, Review-A-validated) is bound to one
explicit Candle computation point/window; an unrelated later Candle window can never supersede
an older computation point (enforced in `select_candle`'s window-scoped lineage resolution).
Candle correction for the *same* computation point remains ordinary Candle correction lineage
(`candle-corrected` → `context_cutoff_source → CandleCorrected`, already representable in §4's
existing invariant). This ADR's temporal-supersession decision (§5 below) applies only to the
six non-Candle analytical roles and explicitly preserves the Candle distinction.

**Authority-neutral framing (`MAJ-02`) — this ADR does not resolve the `context.md`-vs-Chapter-7
Projection terminology tension, and does not turn Context into an authoritative domain-state
owner.** [Chapter 7 §7.4](../constitution/07-module-taxonomy.md) (Locked) fixes exactly what a
Type-2 Projection may and may not do: **forbidden** to "phát sinh authoritative domain fact,
domain decision, hoặc state transition thuộc capability khác... Projection không bao giờ là
authoritative source cho một domain concept"; **permitted** to fold/aggregate, compute derived
values, and "phát sinh operational metadata event về chính nó"; and, on criticality, a
projection consumed by Decision/Risk/Execution "phải khai báo criticality và failure policy
tường minh... khi tính đúng đắn hoặc độ freshness của nó không xác định, consumer phải fail-safe
theo I-6. **Điều này không biến projection thành authoritative source.**" `module-registry.yaml`
currently pins `context-aggregator`'s `module_type: projection` and
`owns_authoritative_state: false`; `feature-context-architecture.md` §5.2/§13 (Package 1.3-B,
Consolidated Stable) already documents, and explicitly preserves unresolved, a terminology
tension between `context.md`'s own §2 envelope framing ("authoritative event record" — the
generic Chapter 8 §8.2 label every event in that section inherits, not a Context-specific
assertion) and the Projection/non-authoritative classification `module-registry.yaml` and
Chapter 7 pin. This ADR is **not authorized to silently resolve that preserved gap**, and does
not attempt to. Accordingly:

1. This ADR does **not** change `module_type: projection`, `owns_authoritative_state: false`,
   [Chapter 7 §7.4](../constitution/07-module-taxonomy.md), or the existing unresolved
   terminology tension in `context.md` — none of `module-registry.yaml`, `context.md`, or
   `feature-context-architecture.md` is edited by this transaction.
2. Adding a canonical `computation_cursor` gives the durable Context projection record
   (`MarketContextSnapshot`/`MarketContextFactInvalidated`) durable knowledge-boundary
   evidence — record-integrity (immutable, cursor-bounded, lineage-preserving, eligible per
   §8) — it does **not** make Context an authoritative source for Structure, Regime, Feature,
   Candle, Strategy, Decision, Risk, or any other business-domain concept. Throughout this ADR,
   Context's own output is referred to as the **Context projection record** — an eligible
   cursor-bounded projection record carrying durable replay evidence — never as "the
   authoritative Context event/fact," to avoid implying domain-state ownership this ADR does
   not grant and Chapter 7 §7.4 forbids.
3. Decision (or Risk) may depend on Context as a critical deterministic projection under
   Chapter 7 §7.4's own criticality clause, with fail-safe behavior when Context is
   unavailable or its freshness/correctness is uncertain (I-6); that dependency does **not**
   convert Context into authoritative domain ownership of anything it aggregates — the
   dependency relationship and the authority classification are two separate axes, and this
   ADR touches only the former (durable evidence a consumer could use to reason about
   freshness/boundary), never the latter.
4. This ADR does **not** resolve whether `context.md`'s own §2 legacy phrase "authoritative
   event record" should later be rewritten to a Projection-consistent term. That question is
   explicitly out of scope here, unless separately governed by its own bounded `context.md`
   amendment transaction (see Consequences).
5. Follow-on Context Event Contract/publication work (Consequences items 2–4) must preserve
   this identical authority boundary — no follow-on transaction may use this ADR as
   justification for reclassifying `context-aggregator` as authoritative, hybrid, or a
   `runtime_service`/`compute_engine` module type.

**Decision:**

**1. Canonical cursor — reuse Chapter 8, do not invent a local schema.** Context's
`computation_cursor` field, wherever it appears (below), is the canonical
[Chapter 8](../constitution/08-event-model.md) §8.5 Replay Cursor **verbatim** — not a
Context-local near-equivalent. `context.md` §20 already commits Context to "áp dụng, không
định nghĩa lại... ordering/replay cursor mechanics (Chapter 5/Chapter 8)"; a parallel schema
would violate that authority boundary Context itself already pins, exactly the reasoning
[ADR-035](./ADR-035.md) applied to Feature via the identical `feature.md` §18 clause and the
Chapter 8 §8.4 (`decision_context_cursor`) reuse precedent.

```yaml
computation_cursor:                       # value type = canonical replay_cursor, Chapter 8 §8.5.1
  recorded_time:                          # Required — knowledge boundary
  input_contract_ref:                     # Required — {contract_id, contract_version},
                                           #   the Context-scoped Input Contract instance
                                           #   this computation pinned (Chapter 8 §8.3.4)
  stream_registry_version:                # Required — must match input_contract_ref's
                                           #   pinned registry version (§8.5)
  lifecycle_frontier:                     # Required — {stream_id, position: {kind, sequence}}
                                           #   on the canonical Lifecycle Stream (§8.3.5)
  stream_positions:                       # Required — map <stream_id> -> <sequence>,
                                           #   cardinality = exactly included_streams of the
                                           #   pinned Input Contract, valid at lifecycle_frontier
                                           #   — never a fixed count, never open-ended, never a
                                           #   cross-stream sequence (ADR-009's no-global-order)
```

**1a. Cursor validity and the `Cursor → Context projection record` relation (`MAJ-R2-01`).**
Reusing Chapter 8 §8.5's schema does not, by itself, define the relation between a
`computation_cursor` value and the Context projection record carrying it — schema reuse alone
leaves open whether a record could claim a cursor from its own future. Two distinct
requirements apply, and this ADR keeps them explicitly separate:

- **Cursor-internal validity is entirely Chapter 8's, unchanged, not redefined locally.** Every
  `computation_cursor` value on a Context projection record must independently satisfy every
  normal Chapter 8 §8.5 cursor invariant exactly as Chapter 8 already owns them — Position →
  Cursor, Lifecycle → Cursor, Registry → Lifecycle, Registry → Contract (§8.5.2), stream-universe
  validity (§8.5.3), and retained/genesis semantics (§8.3.5). This ADR does not restate their
  content beyond citation, and does not create a Context-local variant of any of them.
- **`Cursor → Context projection record` is the one genuinely Context-specific relational
  adaptation this ADR adds** — equivalent in anti-look-ahead purpose to Chapter 8 §8.5.2's own
  `Cursor → Decision` relation (`cursor.recorded_time <= decisionEvent.recorded_time`) and
  [ADR-035](./ADR-035.md)'s identical adaptation for `FeatureComputed`/`FeatureFactInvalidated`.
  For **every** `MarketContextSnapshot` and **every** `MarketContextFactInvalidated`:

```text
computation_cursor.recorded_time <= record.envelope.recorded_time
```

  Equality is permitted when knowledge-cut capture and record append occur within the same valid
  processing boundary. A record whose `computation_cursor.recorded_time` exceeds its own
  `envelope.recorded_time` claims knowledge from its own future — a direct [I-3](../constitution/02-platform-invariants.md)
  violation, the identical class of defect Chapter 8 §8.5.2's `Cursor → Decision` relation exists
  to prevent for Decision. **A cursor that fails any Chapter-8 internal invariant, or fails this
  `Cursor → Context projection record` relation, is an invalid cursor: the record MUST NOT be
  published.** No implementation may silently clamp either timestamp, and no implementation may
  substitute `envelope.recorded_time` for `computation_cursor.recorded_time` or vice versa —
  they remain two independent, both-required fields, exactly as Decision item 3 already
  establishes them as distinct axes.

**1b. Context-scoped knowledge coverage — `COVERS_CONTEXT` (`MAJ-R3-01`).** Item 1a's cursor
invariants prove a single cursor's own internal validity; they do not, by themselves, prove
that a later or differently-captured cursor's knowledge is a superset of an earlier cursor's
knowledge for the SAME Context lineage. Without that additional guarantee, a cursor could gain
one new causally-relevant fact while silently losing visibility of other, unrelated
Context-relevant facts already known at the earlier boundary — producing a "replacement" that
is deterministic at its own cursor but built from strictly less Context knowledge than the
boundary it is meant to supersede. This item closes that gap with a bounded, Context-scoped
**partial** relation — explicitly **not** a platform-wide Replay-Cursor total order.

Define `K_context(R)` — a reasoning-only knowledge-set concept used for correctness
argumentation. It is **not** a payload field, **not** a global cursor ordinal, **not** a
replacement for the canonical Replay Cursor, and **not** a causation set:

```text
K_context(R) = the set of Context-relevant upstream event records fully visible at canonical
               computation_cursor R (full visibility predicate, Decision item 4), under R's
               own pinned Context Input Contract universe — every event family context.md §16
               authorizes Context to consume, including eligible candidates, losing candidates,
               corrections, and invalidations — NOT merely the seven winning
               normalized_input_fact_refs.
```

For two valid canonical Context `computation_cursor` values on the same Context lineage:

```text
R_new COVERS_CONTEXT R_old   iff   K_context(R_old) ⊆ K_context(R_new)
                              AND  lifecycle/topology knowledge does not regress on the
                                   canonical Lifecycle Stream (Chapter 8 §8.3.5) — R_new's
                                   lifecycle_frontier position is at or beyond R_old's own,
                                   using that SAME stream's own valid position ordering,
                                   never a cross-stream comparison.
```

`COVERS_CONTEXT` is explicitly **not**: `R_new > R_old`; a platform-wide Replay-Cursor total
order; an [ADR-009](./ADR-009.md) ordering change; or an ordering relation between independent
stream events. It is set-inclusion / non-regression of Context-relevant visible knowledge for
one Context lineage's own cursor progression, proven entirely from evidence Chapter 8 already
owns.

**Proving coverage — no new cursor field required (`MAJ-R4-01` adds condition 3 below).**
Coverage is proven from the two cursors' own already-required fields (Decision item 1) and the
referenced Input Contract/Stream Registry artifacts they pin:

```text
1. Every Context input stream represented in R_old's valid universe, whose history is
   relevant to the same Context semantics, remains represented in R_new's valid universe.
2. Using stable logical stream_id (Chapter 8 §8.3.1), R_new.stream_positions[stream_id] is
   at or beyond R_old.stream_positions[stream_id] for every such stream — a same-stream
   comparison only; cross-stream sequence comparison is never performed (§8.3.3).
3. R_new.recorded_time is at or beyond R_old.recorded_time. Condition 2 alone does NOT prove
   this leg: neither Chapter 5 nor Chapter 8 guarantees recorded_time is monotonic with
   same-stream sequence, so an implementation could otherwise accept
   R_new.stream_positions[s] >= R_old.stream_positions[s] for every relevant stream while
   R_new.recorded_time < R_old.recorded_time — silently losing any event that was visible at
   R_old solely under leg 3 of the full visibility predicate (Decision item 4:
   E.recorded_time <= R.recorded_time). For every E in K_context(R_old):

       E.recorded_time <= R_old.recorded_time      (R_old's own leg-3 visibility, by the
                                                      definition of K_context(R_old))
       R_old.recorded_time <= R_new.recorded_time   (this condition)
       therefore E.recorded_time <= R_new.recorded_time         (transitivity)

   Together with conditions 1, 2, 4, 5, and 6, this closes the recorded-time leg of the
   set-inclusion proof that condition 2 alone leaves open.
4. R_new.lifecycle_frontier does not regress relative to R_old.lifecycle_frontier on the
   canonical Lifecycle Stream (§8.3.5) — both positions compared on the SAME stream only.
5. A stream retired between R_old and R_new follows Chapter 8 §8.3.5's own existing
   Retained-in-Universe / terminal-position semantics — retirement never silently drops
   that stream's already-visible history from coverage.
6. A later Input Contract or Stream Registry version is permitted under R_new ONLY if the
   resulting cursor still preserves visibility of every Context-relevant record visible at
   R_old. If a newer Input Contract or registry version would drop such knowledge —
   K_context(R_old) NOT SUBSET OF K_context(R_new) — then R_new does NOT cover R_old for
   this lineage transition, and this ADR does not permit that transition to author a new
   current-valid Context lineage result. An intentional semantic reset of this kind, if
   ever desired, requires its own separately governed semantics — it is never hidden
   inside ordinary cursor replacement under this ADR.
```

**Recorded-time non-regression is not an ordering claim (`MAJ-R4-01`).**
`R_new.recorded_time >= R_old.recorded_time` does **not** mean `R_new > R_old`, and does not by
itself establish event ordering between the two cursors or between any events they bound — the
Ordering-Authority discipline ([Chapter 5 §5.4](../constitution/05-time-model.md)/
[Chapter 8 §8.3.3](../constitution/08-event-model.md), Locked) is entirely unaffected and is
never derived from this condition. Condition 3 exists solely to prevent regression on the
Recorded-Time visibility axis (Decision item 4 leg 3); `COVERS_CONTEXT` remains a **partial**
knowledge-coverage relation formed from conditions 1–6 together, never a scalar comparison of
any single field.

Coverage proof never compares `sequence` across different stream identities, never requires
`stream_registry_version`/`contract_version` equality between the two cursors, and never
constructs a scalar cursor rank. A legitimate future Input-Contract version transition (adding
streams, following a governed stream migration, pinning a later Stream Registry version) is
never prohibited by this item — it is only required to still satisfy `COVERS_CONTEXT` for any
cursor progression it participates in as `R_new`.

**The semantic definition remains authoritative.** The direct semantic truth this item defines
is `K_context(R_old) ⊆ K_context(R_new)` together with lifecycle/topology non-regression;
conditions 1–6 above are the canonical field-level proof sufficient to establish it under the
current event-log model (Chapter 5/Chapter 8, as owned today — neither redefined nor amended
here). If an unusual future topology or migration makes this proof insufficient or inapplicable
for an ordinary same-lineage transition, this ADR fails closed unless a separately-governed
proof mechanism is established for that case — set inclusion is never weakened, and no scalar
cursor rank is invented as a substitute.

**Coverage vs. causation — kept separate.** `K_context(R)`/`COVERS_CONTEXT` is
knowledge-boundary correctness evidence — it proves non-regression, never *why* an invalidation
occurred. `causation_refs` (Decision item 7) is direct-causal-predecessor evidence — it proves
*why*. Coverage is never reduced to a `causation_refs` question, and `causation_refs` is never
expanded to contain every element of `K_context(R_new) - K_context(R_old)`; only the existing
minimal-complete direct cause set from Decision item 7 belongs in `causation_refs`. These two
concepts remain structurally distinct throughout this ADR.

**2. `computation_cursor` on `MarketContextSnapshot` — every fact pins its own boundary.**
Every `MarketContextSnapshot`, original or correction replacement alike, carries its own
required `computation_cursor` — the exact knowledge boundary under which §8's Eligible Upstream
Fact selection was evaluated to produce *that* fact. A replacement snapshot does **not** inherit
or copy the fact it supersedes' cursor; it pins its own actual re-evaluation boundary,
independent of `supersedes_fact_ref`'s target. This mirrors §15's own already-Locked prose
("mỗi fact" reconstructed "tại đúng computation cursor của CHÍNH fact đó") and
[ADR-035](./ADR-035.md)'s identical rule for `FeatureComputed`.

**3. `computation_cursor` on `MarketContextFactInvalidated`.** Every
`MarketContextFactInvalidated` also carries its own required `computation_cursor` — the
`R_later` boundary at which Ride proves the invalidated snapshot `C` is no longer the
CURRENT-VALID lineage-head result for its computation point (`MIN-01` — this is a later
knowledge-boundary transition, never a rewrite of `C`'s own historical correctness; see the
bitemporal clarification below Decision item 8). This is durable evidence distinct from: `C`'s
own `R_original` (a different fact's field, proving what `C` itself could see, not what
triggered its invalidation); `envelope.recorded_time` (append time — a different axis, per
`context.md` §14's explicit prohibition on substituting it for cursor semantics, carried
forward from `feature.md` §12/[ADR-034](./ADR-034.md)'s identical prohibition); and the
eventual replacement's own `computation_cursor` (a third, independent fact's boundary, per
Decision item 2 above). Fresh authority check performed: no existing mechanism —
`normalized_input_fact_refs`, `causation_refs`, `envelope.recorded_time`, or any current
Chapter-8/context.md field — durably proves `R_later` (see Ground-truth items 1–3 above);
this ADR therefore does not STOP on this point and proceeds with the invalidation cursor,
consistent with [ADR-035](./ADR-035.md)'s identical conclusion for `FeatureFactInvalidated`.

**3a. Universal current-lineage invalidation knowledge-boundary precondition (`MAJ-R4-02`).**
Decision item 1b's `COVERS_CONTEXT` relation, as first wired into this ADR, protected only the
temporal eligible-winner-supersession trigger (Decision item 5's own condition 7). But every
`MarketContextFactInvalidated` that changes which Context projection record is the
CURRENT-VALID lineage head for its computation point carries the identical knowledge-regression
risk item 1b closes — regardless of which trigger produced it: Decision item 5's temporal
trigger, OR Decision item 6's preserved direct upstream correction triggers (`CandleCorrected`
for the exact computation point, `StructureFactInvalidated`/`StructureRecomputed`,
`RegimeFactInvalidated`/replacement, `FeatureFactInvalidated`/replacement). An invalidation
cursor can be entirely valid for, and cause-set-visible under, its own specific trigger while
still having, incidentally, lost visibility of other, unrelated Context-relevant knowledge
already known at the invalidated snapshot's own boundary — the same failure shape item 1b
closes, simply reachable through a different trigger door.

This ADR therefore states **one** universal precondition, controlling for every trigger class,
never duplicated per trigger:

```text
For every MarketContextFactInvalidated targeting current-valid Context projection record C:

  R_later    = invalidation.computation_cursor    (Decision item 3, above)
  R_original = C.computation_cursor               (Decision item 2, above)

  R_later COVERS_CONTEXT R_original   (Decision item 1b)

  MUST hold before the invalidation may publish as a current-valid lineage transition.
```

If this precondition fails, the proposed invalidation MUST NOT author a current-valid lineage
transition — regardless of whether the trigger-specific cause is otherwise entirely valid.
Historical/counterfactual analysis under that cursor remains allowed; only current-valid
publication is blocked.

**This precondition answers only "did knowledge regress?" — it never answers "why is `C` no
longer current-valid?"** That second question remains entirely the province of the
trigger-specific rules: Decision item 6's existing governed direct-correction/invalidation
semantics for the direct-correction path, and Decision item 5's role-resolution-delta test
(conditions 1–6) for the temporal-supersession path. Coverage does not itself prove a
correction occurred, and trigger-specific causation does not itself prove knowledge
non-regression — both must independently hold. Decision item 5's own condition 7 references
this identical universal precondition in its own local context (temporal supersession) rather
than defining a second, competing rule — there is exactly one authoritative
`COVERS_CONTEXT`-based invalidation rule, not two subtly different copies.

**Candle direct correction is NOT exempt from this universal precondition** — Candle remains
exempt only from the six-role temporal-winner-supersession trigger (Ground-truth item 6/Decision
item 6, unaffected). If `CandleCorrected` directly invalidates `C`, `R_later COVERS_CONTEXT
R_original` still applies; this does not permit an unrelated later Candle window to replace the
computation point — `target_computation_point_ref`'s window-scoped lineage resolution
(CONTEXT-CORE-A-MAJ-01, Review-A-validated) is unaffected and remains the sole authority binding
a computation to its Candle window. Existing exact-same-window Candle correction semantics
(`context_cutoff_source → CandleCorrected`) are otherwise unchanged.

**4. Full visibility predicate — apply Chapter 8, do not redefine it.** An upstream event `E`
is visible at Context `computation_cursor R` **if and only if all of the following hold**
(identical in structure to [ADR-035](./ADR-035.md)'s Feature-scoped predicate, applied here to
Context):

```text
1. E.stream_id is in R's valid stream universe — E.stream_id is one of
   R.input_contract_ref's included_streams, and that stream's inclusion is valid at
   R.lifecycle_frontier (Chapter 8 §8.3.5 Retained-in-Universe semantics);
2. E.sequence <= R.stream_positions[E.stream_id] — an IN-STREAM position boundary only;
   NO cross-stream sequence comparison is ever performed (Chapter 8 §8.3.3);
3. E.recorded_time <= R.recorded_time (Chapter 5 §5.3's recorded-time boundary).
```

Any leg failing makes `E` not visible at `R`. Context still **independently** applies its own
effective-time cutoff (`context.md` §8 Phase 1 step 3, §14(b)) on top of this — visibility and
effective-time eligibility remain two separate, both-required conditions, exactly as `context.md`
§14 already states ("(a) một mình KHÔNG đủ"); this ADR does not collapse them.

**5. Temporal eligible-winner supersession — a role-resolution delta, bounded to the six
non-Candle analytical roles (`MAJ-03`, coverage condition 7 added by `MAJ-R3-01`, condition 7
now references the universal precondition of Decision item 3a per `MAJ-R4-02`).** For a
stored Context projection record `C`, evaluated
at `computation_cursor R_original`, a later `computation_cursor R_later` **requires invalidation
of `C`** when, for at least one of Structure / volatility Regime / directional-persistence
Regime / volatility-metric Feature / directional-persistence-metric Feature /
distance-to-last-confirmed-swing Feature, exact `context.md` §8 re-evaluation of that SAME
Context computation point / SAME Context Definition under CURRENT authority establishes a
**role-resolution delta**:

```text
1. the role resolved to old ref A at R_original (C's currently-cited ref for that role);
2. one or more relevant upstream records/events needed to establish the role's state at
   R_later were NOT visible (full predicate, item 4) at R_original;
3. those exact records/events ARE fully visible (full predicate, item 4) at R_later;
4. effective-time eligibility (context.md §8 step 3) and producer-domain correction-lineage
   semantics already fixed in structure.md/regime.md/feature.md (never invented or redefined
   by this ADR) are applied exactly, using ONLY those authorities' own existing rules;
5. exact context.md §8 selection at R_later, for the SAME computation point and SAME Context
   Definition, yields either a DIFFERENT winning role ref for that role than A, OR causes
   that role to become missing/pending (§9) at R_later;
6. C therefore ceases to be the CURRENT-VALID lineage head/result for that computation point
   at R_later (see MIN-01 bitemporal clarification below — this does not rewrite C's own
   historical correctness at R_original);
7. R_later COVERS_CONTEXT R_original — the universal current-lineage invalidation
   knowledge-boundary precondition (Decision item 3a, `MAJ-R4-02`; the `COVERS_CONTEXT`
   relation itself is Decision item 1b's) applied to this trigger. A historical,
   counterfactual, partially-regressed, or incomparable cursor that fails this precondition
   MUST NOT author a temporal invalidation of the current-valid Context lineage head, even if
   conditions 1-6 above otherwise hold — it may still be evaluated for
   historical/counterfactual replay analysis, but it may never produce a current-valid
   invalidation transition.
```

The previously-selected role ref `A` is **not** required to have been itself invalidated — this
is a temporal winner-change condition, structurally distinct from repaint (§15's "KHÔNG BAO GIỜ
bị ghi đè tại chỗ" is unaffected: `C` is never mutated, only invalidated-and-replaced,
append-only). This generalizes [ADR-034](./ADR-034.md)'s `eligible_swing_selection_superseded`
condition (a)–(d) from Feature's single Eligible-Swing role to Context's six analytical roles,
preserving the identical condition-2-is-load-bearing distinction: a candidate that was
**already** visible at `R_original` but not selected is a computation *defect* in the original
fact (§8's algorithm not correctly applied), never this temporal-supersession cause — that
distinction is preserved unchanged here. Unlike v0.1's single-newly-visible-candidate framing,
step 2 above explicitly allows the delta to be established by a SET of one or more records
(Decision item 7's cause-ref set, below) — a single new record is the common case, but a
compound transition (e.g. a later-visible successor that is itself subsequently invalidated,
requiring both records as proof) is equally representable.

**6. Preserve direct upstream correction flow — integrate, do not replace (universal coverage
precondition applies, `MAJ-R4-02`).** Existing direct correction/invalidation cases remain
valid and unmodified by this decision: `CandleCorrected` for the exact computation point
(Candle role, item 6 of Context above); `StructureFactInvalidated` / `StructureRecomputed`;
`RegimeFactInvalidated`/replacement; `FeatureFactInvalidated`/replacement. The
temporal-supersession condition (item 5) is an **additional** trigger for
`MarketContextFactInvalidated`, not a replacement of these. Every one of these direct-correction
triggers is equally subject to Decision item 3a's universal current-lineage invalidation
knowledge-boundary precondition (`R_later COVERS_CONTEXT R_original`) before it may publish a
current-valid `MarketContextFactInvalidated` — this item's own trigger-specific
correction/invalidation semantics (which existing upstream event legitimately causes an
invalidation) remain entirely unchanged and answer a different question (*why* `C` is no longer
current-valid), never the coverage question (*did knowledge regress?*) item 3a answers.

**7. Invalidation representation — minimal change, per-role cause-ref SET, not one ref
(`MAJ-03`).** `context.md` §4's `affected_upstream_roles` array and `causation_refs` (a single
flat, canonical, deduplicated event-reference set — never a second, competing role-mapping
structure) are preserved. The change this ADR proposes to a follow-on `context.md` amendment
(not made here): for each role listed in `affected_upstream_roles`, its cause is no longer
assumed to be exactly one `causation_refs` entry — it is the **minimal complete deterministic
evidence set** required to prove that role's resolution delta at `R_later` (Decision item 5),
containing **one or more** exact direct upstream event refs, never an unrelated ref, never a
duplicate. Each entry is either (a) a correction/invalidation event that makes the stored role
ref invalid or missing (the six existing mappings, ground-truth item 5, unchanged — e.g.
`StructureFactInvalidated`), or (b) the later-visible authoritative fact itself (a plain
`structure-recomputed`/`break-of-structure-detected`/`change-of-character-detected`/
`regime-classified`/`feature-computed` event) that becomes the new §8 winner, or (c), when the
delta is compound, **both** a later-visible successor and that successor's own subsequent
invalidation (e.g. `{B, I_B}` — a `regime-classified` fact `B` plus the `RegimeFactInvalidated`
that later invalidates `B`, when the role resolves missing/pending because `B` itself did not
survive, per Ground-truth's compound example). **Role attribution remains fully deterministic
without a new schema field:** each referenced event's own governed type + role discriminant
(`regime_dimension`/`feature_type`, where applicable) + its target/ref relationship
(`invalidated_fact_ref`/`supersedes_fact_ref`, when present) unambiguously identifies which
role and which branch it belongs to — attribution is derived from these relationships, never
from `causation_refs`' list order. When two or more roles are affected independently in the
same `MarketContextFactInvalidated`, each role's cause set is resolved independently against
Decision item 5, and all resulting refs across all affected roles are unioned and deduplicated
into the one flat `causation_refs` array — `invalidated_fact_ref` remains separately required
exactly as existing Context invalidation semantics already require, unaffected. This satisfies
the existing "dedup cascade" principle §4 already cites from `structure.md` §10: one
`MarketContextFactInvalidated` per affected fact, listing every affected role and its complete
exact cause set, regardless of which branch (a)/(b)/(c) applies to each role independently.
Deterministic role→cause attribution is achievable entirely within the existing
`affected_upstream_roles` + flat `causation_refs` structure — no new field is required, and
this ADR does not introduce one.

**8. Re-evaluation result and replacement-cursor relation (`MAJ-04`, Case B corrected by
`MAJ-R2-02`, strengthened by `MAJ-R3-01`, coverage chain clarified by `MAJ-R4-02`).** At
`R_later`, if invalidation is triggered (item 5 or item 6): if any required
role is missing/pending at `R_later`, `C` is invalidated but **no** replacement is emitted until
§9 permits a complete snapshot; never stale-fallback to `C`; never fall back to an older Context
window as a substitute for the affected computation point. If all seven roles resolve, exactly
one replacement Context projection record is permitted for the SAME `(context_subject_id,
effective_window)` lineage, under exactly one of two legal cases — **never a third, implicit
case**:

```text
Case A — SAME re-evaluation boundary:
  replacement.computation_cursor == invalidation.computation_cursor == R_later
  The replacement's role refs/values MUST be exactly the §8 result already established
  by the R_later re-evaluation that triggered the invalidation — no separate recomputation
  is performed or permitted; reusing that exact result is correct precisely because no
  cursor advance occurred between invalidation and replacement.

Case B — Fresh subsequent re-evaluation boundary (no replacement is emitted from the exact
R_later re-evaluation itself):
  R_replacement != R_later is a possible CONSEQUENCE of this case, never its DEFINITION.
  Ride's no-global-total-order discipline (Chapter 8 §8.3/ADR-009) means two Replay Cursors
  can be later, earlier, or partially incomparable to one another — raw inequality between
  R_replacement and R_later proves nothing about which cursor's knowledge is a superset of
  the other's, so it is never used as, or substituted for, a proof of "later."
```

**Case A is legal only because Decision item 3a's universal precondition already holds at the
invalidation boundary (`MAJ-R4-02`).** Before any `MarketContextFactInvalidated` may publish,
`R_later COVERS_CONTEXT R_original` (item 3a) must already be proven. Case A's
`replacement.computation_cursor == invalidation.computation_cursor == R_later` therefore
inherits that identical, already-non-regressed knowledge boundary directly — no separate
coverage test is required for Case A beyond the universal precondition already established at
invalidation time.

Case B is governed by ten explicit sub-rules — all must hold before a replacement may
publish:

```text
1. R_replacement is captured as a genuine, valid canonical computation_cursor (Decision
   item 1) via the future governed Context Input-Contract/frontier mechanism (Decision
   item 9) — never invented ad hoc by this ADR.
2. R_replacement MUST be a genuine, non-counterfactual evaluation boundary for the actual
   replacement operation performed. A historical or counterfactual cursor value MUST NOT
   be used to manufacture a new current-valid lineage replacement.
3. "Later," "fresher," or "supersedes" is NEVER proven by: raw recorded_time alone; raw
   sequence; cross-stream sequence comparison; simple cursor inequality; or wall-clock
   ordering. No such proof is invented by this ADR, and none is required — correctness
   comes from rules 4-6 below instead.
4. Every IN-SCOPE upstream event/fact belonging to the invalidation's own minimal-complete
   role-resolution cause set (Decision item 7) that participates in Context state
   computation MUST be fully cursor-visible (full predicate, Decision item 4) at
   R_replacement. In particular, the replacement MUST NOT evaluate from a knowledge
   boundary that omits the exact evidence which caused C to lose current-valid status —
   if it did, the "replacement" would not actually incorporate the knowledge the
   invalidation was based on.
5. Exact context.md §8 selection is independently rerun at R_replacement for the same
   computation point and same Context Definition. The cached R_later role-selection
   result is NEVER reused under a different cursor.
6. Replacement role refs/values/normalized_input_fact_refs are exactly the result of
   that fresh rerun at R_replacement — never a mix of R_later's cached result and
   R_replacement's own evaluation.
7. MAJ-R2-01's Cursor -> Context projection record relation applies identically:
   R_replacement.recorded_time <= replacement.envelope.recorded_time.
8. If the cause/state evidence rule 4 requires cannot be represented as visible under
   R_replacement's own valid Input Contract stream universe, this fails closed: NO
   replacement is published under this attempt. Only a re-evaluation whose cursor
   genuinely resolves the required evidence may proceed.
9. R_replacement MAY validly pin a later governed Input Contract or Stream Registry
   version than R_later, if the platform's own governed lifecycle permits that version
   to exist and be pinned at that boundary. Raw equality of registry/contract version
   between R_replacement and R_later is NEVER required — correctness here rests on
   canonical cursor validity (rule 1), genuine non-counterfactual capture (rule 2),
   required cause/state visibility (rule 4), and fresh §8 recomputation (rule 5), never
   on inventing a cross-version total order.
10. R_replacement MUST COVERS_CONTEXT R_later (Decision item 1b, `MAJ-R3-01`) — Context
    knowledge non-regression from the invalidation boundary to the replacement boundary,
    IN ADDITION to rules 1-9 above. Rule 4's cause-set visibility is necessary but is NOT
    sufficient by itself: a replacement that sees the invalidation's own cause set but has
    lost visibility of other, unrelated Context-relevant knowledge already known at
    R_later (e.g. R_later saw {A, B, X}, R_replacement sees only {A, B}) fails this rule
    and MUST NOT publish. A replacement that sees a strict superset (e.g. {A, B, X, Y})
    satisfies this rule regardless of whether Y changes the final §8 result.
```

**Resulting coverage chain (`MAJ-R4-02`).** Decision item 3a establishes `R_later
COVERS_CONTEXT R_original` for every invalidation before it may publish; rule 10 above
independently establishes `R_replacement COVERS_CONTEXT R_later` for Case B. By transitivity of
set inclusion:

```text
K_context(R_original) ⊆ K_context(R_later) ⊆ K_context(R_replacement)
```

This is **not** a global total ordering and does **not** claim `R_replacement > R_original` in
any wall-clock or cross-stream sense — it is transitive set inclusion for one Context lineage's
own knowledge boundary, established from two separately-proven local `COVERS_CONTEXT`
relations, never inferred from cursor inequality. For Case A, `R_replacement == R_later`, so the
chain collapses to the single relation item 3a already proved.

**Causation guardrail (unchanged by this correction):** rule 4's cause set is exactly Decision
item 7's `causation_refs` set — every member must remain a genuine **direct domain causal
predecessor/prerequisite** of the Context invalidation, per [Chapter 6 §6.7](../constitution/06-identity-model.md)/
[Chapter 8 §8.2.3](../constitution/08-event-model.md) (Locked), never a transitive or
audit-only reference included merely because it happens to be relevant. Case B's
visibility-at-`R_replacement` requirement (rule 4) does not, and must not be read to, expand
`causation_refs` into a generic evidence bag — it requires only that the refs item 7 already
requires be visible under the new cursor, adding no new member class. Rule 10's `COVERS_CONTEXT`
requirement (`MAJ-R3-01`, Decision item 1b) is a separate, additional evidentiary layer, not a
relaxation of this guardrail: coverage never substitutes for causation, and `K_context(R_new) -
K_context(R_old)` is never poured into `causation_refs` merely because rule 10 requires it be
covered — see item 1b's own "Coverage vs. causation" paragraph.

The replacement still supersedes the invalidated lineage head and remains in the SAME
`(context_subject_id, effective_window)` lineage, per existing Context correction rules
(Decision item 2 — `computation_cursor` is never inherited, independent of which case
applies). This distinction is required even when all seven roles were already complete at
`R_later` — a successful `R_later` re-evaluation is proof that a replacement COULD have been
produced at that exact boundary; it is never proof that the SAME winner set remains correct
under a materially different cursor a genuine replacement actually publishes under. An
implementation MUST record which case applied — Case A is the exact identity
`replacement.computation_cursor == invalidation.computation_cursor`; anything else is Case B,
governed by the ten sub-rules above, never assumed "later" by inequality alone.

**Bitemporal clarification (`MIN-01`) — historical truth vs. later current validity.** `C`
remains **immutable and historically correct** as the Context projection result genuinely
produced under `computation_cursor R_original` — temporal invalidation never rewrites that
historical fact, and never claims `C`'s own original evaluation was wrong. What changes at
`R_later` is only that `C` is no longer the **current-valid lineage head/result** for its
computation point — a later-knowledge-boundary transition, recorded exactly like every other
Context correction (append-only, §15's no-repaint invariant unaffected). Replay behavior is
unaffected and already correct under existing Context semantics: replay at a cursor before the
invalidation's own `recorded_time` still observes `C` as valid (§14's anti-look-ahead rule,
unaffected); replay at a cursor at or after the invalidation observes the invalidation, and the
replacement or `PENDING_CORRECTION` state as appropriate (§13, unaffected). This ADR changes
which durable evidence justifies a temporal invalidation (Decision item 5) — it does not alter
`context.md`'s existing no-repaint or bitemporal-truth invariants in any way.

**9. Context Input Contract binding — requirement only, not authored here.** This ADR

pin exactly one Context-scoped Input Contract instance under Chapter 8 §8.3.4. The expected
included-stream universe is derivable from existing authority — `market-data-ingestion-candle`,
`structure-engine-structure`, `raw-regime-engine-regime`, `feature-engine-feature` (fresh-read

**not** author, publish, or activate that Input Contract artifact; that is deferred to a
separate, bounded follow-on transaction, the identical ordering [ADR-035](./ADR-035.md)
established for Feature.
