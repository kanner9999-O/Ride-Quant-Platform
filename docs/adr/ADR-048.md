## Decision

Select, as a Draft candidate for Review A and Product Owner decision, the representation derived and
reviewed (through v0.3, `CLEAN`) and bounded-corrected in this transaction (v0.4, pending fresh
Review A) in `event-contract-causal-dependency-representation-001.md`, as the canonical
machine-readable Event Contract mechanism satisfying Chapter 8 §8.2.3's `dependency_authority:
per_effect_event_contract` requirement.

### 1. Canonical field — new top-level sibling of `ADR-039`'s shape

```text
causal_state_dependency_declaration
```

A new top-level field on the Event Contract version-artifact, sibling to `event_class`/
`allowed_streams`/`merge_constraints`/`payload_shape`/`payload_semantics_and_invariants`/
`compatibility_commitment` (`ADR-039`). It MUST NOT be placed under `payload_semantics_and_invariants`
(a narrative/prose field by `ADR-039`'s own illustrative shape, with no machine schema for anything
nested inside it), under `merge_constraints` (a distinct Chapter 8 §8.3.4 ordering concept — see
*Separation from `merge_constraints`* below), or in processor/runtime code (directly prohibited by
Chapter 8 §8.2.3).

### 2. Declaration modes — closed sum type, exactly two, no default

```text
mode: vacuous | exhaustive
```

`mode` is **required**, has **no default**, and no value other than these two is valid. There is no
`open` mode, no `partial` mode, and no `closed: false` escape hatch — every Event Contract using this
field commits to one of exactly two fully-specified postures.

**`mode: vacuous`:**

```yaml
causal_state_dependency_declaration:
  mode: vacuous
```

Valid only when the `event_type`'s `causation_refs` is canonically empty for every instance (Chapter 8
§8.2.1's own root-event cardinality). The `roles` field is **prohibited** under this mode — its mere
presence is a malformed declaration. A runtime event instance with non-empty `causation_refs` under an
Event Contract declaring `mode: vacuous` is an integrity violation, fail closed. `VACUOUS` is a
declaration **mode**, never a role classification value.

**`mode: exhaustive`:**

```yaml
causal_state_dependency_declaration:
  mode: exhaustive
  roles:
    - role_id: <unique identifier within this exact Event Contract version-artifact>
      selector: { ... }           # see §3
      cardinality: { ... }        # see §4
      classification: STATE_DEPENDENCY | EXTERNAL_NON_STATE_CAUSE
      apply_time_requirement: >
        Self-contained free-text rationale citing exactly what authoritative application does and
        does not need from this cause, consistent with Chapter 8 §8.2.3's apply-time test. MUST stand
        on its own — it may not merely say "see derivation artifact" or equivalent.
```

Every entry of the effect event's own `causation_refs` MUST match exactly one declared role (the
exactly-one-match rule, §5). `role_id` is **required**, unique **within this exact Event Contract
version-artifact** (never across contracts or across versions), and is stable only within the semantic
identity of that one immutable version — this Decision creates **no** platform-wide `role_id`
registry; the same label may be reused with unrelated meaning in a different Event Contract or a later
version of the same `contract_id` without conflict.

**No required role-level `authority` field (fixes `ADR048-A-MAJ-03`).** The role shape above
deliberately carries no `authority` field citing an external analysis artifact. Requiring one would
conflict with `ADR-039`'s self-contained Event Contract authority model: once `Published`, the Event
Contract version-artifact itself is the canonical authority for its own exact semantics, and a mutable
Draft analysis artifact MUST NOT become a required interpretive authority or runtime dependency — no
validator implementing this mechanism reads any analysis artifact. Reviewed analysis (e.g. the
state-dependency derivation) supplies **authoring evidence** during drafting/review; the Published
Event Contract itself owns the resulting classification declaration. Where drafting-history citation
is useful, it belongs in `ADR-039`'s already-existing top-level `provenance` field (non-normative,
not required to interpret the Published artifact, not read by runtime classification, and never
competing with the Event Contract's own authority) — or in Review A evidence/ADR documentation — never
as a required canonical runtime role field.

### 3. Role classification enum — exactly two values, `VACUOUS` excluded

```text
STATE_DEPENDENCY
EXTERNAL_NON_STATE_CAUSE
```

No third role-classification value exists. `VACUOUS` belongs exclusively to the declaration **mode**
(§2) — a role can never be classified `VACUOUS`, eliminating the impossible state of a role that
simultaneously claims to be vacuous and yet matches a concrete `causation_ref`.

### 4. Selector — closed tagged union

A role's `selector` is **exactly one** of two kinds — never both, never neither:

```text
kind: payload_field
kind: by_target
```

**`kind: payload_field`:**

```yaml
selector:
  kind: payload_field
  path: invalidated_fact_ref
```

`path` resolves directly in the **effect event's own** payload, at the type already fixed by
`payload_shape` (`event_record_ref`, or an array/list of `event_record_ref`). Every reference obtained
there MUST also literally appear in the effect event envelope's own `causation_refs` — a payload-
declared reference absent from the envelope set is an integrity violation, fail closed (this is the
exact discipline `structure.md`'s own `invalidated_fact_ref` field already documents: *"trùng với
causation_refs"*). This selector never reads any **target** event's payload — only the effect's own.

**`kind: by_target`, static form (`match`):**

```yaml
selector:
  kind: by_target
  match:
    event_types: [CANDLE_CLOSED, CANDLE_CORRECTED]
    contract_ids: [candle-closed, candle-corrected]
```

At least one of `event_types`/`contract_ids` is **required**; either may be omitted. When **both**
are present, the predicates are **conjunctive** (AND) — the target's own `event_type` must belong to
the `event_types` allow-set **and** the target's own `event_contract_ref.contract_id` must belong to
the `contract_ids` allow-set. These two lists are **independent allow-sets**, never paired by array
position — there is no index-N-to-index-N correspondence between `event_types` and `contract_ids`;
introducing one would require a new, separately-governed grammar extension, not an interpretation of
this shape. Matching uses only information available from the target's own envelope and pinned
`event_contract_ref` identity during the existence-resolution Chapter 8 §8.2.3 already mandates for
every `causation_ref` — target **domain payload is never read**. This selector does not itself
legitimize an otherwise-invalid target event / `event_contract_ref` pairing; all ordinary Event
Contract validity rules continue to apply to the target independently.

**`kind: by_target`, discriminated form (`discriminant`):**

```yaml
selector:
  kind: by_target
  discriminant:
    payload_field: invalidation_cause
    cases:
      swing_invalidated:
        event_types: [SWING_INVALIDATED]
        contract_ids: [swing-invalidated]
```

`discriminant` and `match` are **mutually exclusive** on the same role. `discriminant.payload_field`
reads **only the effect event's own** payload — never the target's. Each entry under `cases` follows
the identical static-matching rule (at least one of `event_types`/`contract_ids`; AND when both are
supplied). There is **no implicit/default case**: a discriminant field missing or unresolvable on the
effect's own payload is an integrity violation, fail closed; a resolved discriminant value absent from
`cases` is likewise an integrity violation, fail closed. Target domain payload is never read.

### 5. Cardinality — closed union, exactly two forms

```text
Form A — exactly:
cardinality: { exactly: <non-negative integer> }

Form B — range:
cardinality: { min: <non-negative integer>, max: <non-negative integer | null> }
```

Form A permits **only** the `exactly` key. Form B requires **both** `min` and `max`; `min >= 0`; when
`max` is an integer, `max >= min`; `max: null` means unbounded. **Rejected as malformed:** `exactly`
combined with `min`/`max` on the same role; any unknown key; negative integers; `min > max`; a range
form missing `min` or `max`; an empty `cardinality` mapping; non-integer numeric values.

### 6. Matching algorithm — normative, order-independent, two-phase

This Decision makes the following algorithm **normative**, not merely descriptive, for any validator
implementing `dependency_authority: per_effect_event_contract` against an Event Contract declaring
this field.

**Canonical-locator uniqueness precondition (fixes `ADR048-A-MAJ-02`), evaluated before Phase 1.**
Chapter 8 §8.2.3 defines `envelope.causation_refs` as zero-to-many `event_record_ref` entries, each a
qualified reference keyed by the canonical locator `(stream_id, sequence)` — `event_id` is a
verification field only and never distinguishes two entries that resolve to the same locator. Chapter
8 does **not** itself declare locator uniqueness within one event's `causation_refs` list; this ADR
adds a deterministic validation constraint, scoped specifically to use of the
`causal_state_dependency_declaration` mechanism, that it does: **within one effect event's own
`envelope.causation_refs`, canonical locators `(stream_id, sequence)` MUST be unique.** If two entries
share the same canonical locator, fail closed — *duplicate canonical locator in `causation_refs`*
(§9 item 19) — **regardless of whether their `event_id` values are equal**: same locator denotes the
same physical event, so a duplicate entry carries no additional causal meaning; allowing multiplicity
here would make role cardinality and exactly-one-match validation ambiguous and redundant for no
benefit; and if the two entries' `event_id` values actually differ at the same locator, Chapter 8
§8.2.3's own tuple-consistency invariant independently fails first regardless of this rule. This
constraint does **not** mutate Chapter 8, and does **not** claim Chapter 8 already required
uniqueness — it is a new deterministic precondition this ADR introduces for its own mechanism only.

Let `C` denote the finite collection of `envelope.causation_refs` entries **after** this
canonical-locator uniqueness precondition has been validated. Every subsequent step below reasons
over `C` — never over an unchecked list that might silently lose multiplicity if naively treated as a
mathematical set before uniqueness is confirmed.

Confirmed against the reviewed representation derivation v0.4: none of the 10 reviewed event types,
the 2 Candle illustrative examples, or the mixed-case capability hypothetical rely on or produce
duplicate canonical locators within one event's `causation_refs` — this precondition creates no
conflict with any currently-reviewed semantics.

**Phase 1 — independent match-set computation.** For **every** declared role `r`, compute its complete
match set `M(r)` against `C`, the full, original, unmutated causation_refs collection (post
uniqueness-validation per the precondition above). A role's evaluation never consumes, removes, or
treats any entry of `C` as "claimed" by an earlier-evaluated role; it never operates on a
remaining/unclaimed subset; it never stops early because a cardinality budget was nominally reached.
Every role is evaluated **independently** of every other role and of its own position in the `roles`
list — `payload_field` roles resolve their candidates from the effect's own payload (cross-checked
against the envelope set, §4); `by_target` roles (static or discriminated) test **every** entry of `C`
against their own allow-set(s), independently.

**Phase 2 — cardinality and exactly-one-role validation.** For every role `r`, validate its declared
`cardinality` against `|M(r)|`; unsatisfied → fail closed. For every entry `c` in `C`,
compute `matches(c) = { r : c ∈ M(r) }` and require `|matches(c)| = 1`:

```text
0 matches  → FAIL CLOSED (unclaimed, never defaulted)
1 match    → classification = that role's declared classification
>1 matches → FAIL CLOSED (ambiguous overlap)
```

**Role declaration order has zero semantic effect anywhere in this algorithm.** An optional role (e.g.
`{min: 0, max: 1}`) never legalizes overlap with another role — if a `causation_ref` matches both, it
still has more than one match and validation still fails, regardless of either role's own cardinality
permitting zero.

### 7. Application of the two classification values — Chapter 8's own semantics, unchanged

This Decision does **not** redefine what `STATE_DEPENDENCY` or `EXTERNAL_NON_STATE_CAUSE` mean at
apply time — it only fixes **where** and **how** that already-Locked Chapter 8 semantic is declared.

- **`STATE_DEPENDENCY`:** the causal target's required payload/state MUST belong to the consuming
  Input Contract's apply set / input scope / cursor universe, and participate in the applicable
  completeness/frontier accounting — exactly Chapter 8 §8.2.3's existing rule.
- **`EXTERNAL_NON_STATE_CAUSE`:** only identity/existence/commit proof is required; the cause is
  **outside** the merged apply set/frontier; no synthetic `stream_position` is fabricated for it; the
  target's **domain payload** must not be read to perform authoritative application — exactly Chapter
  8 §8.2.3's existing rule.

### 8. Separation from `merge_constraints`

`merge_constraints` ([Chapter 8 §8.3.4](../constitution/08-event-model.md)) and
`causal_state_dependency_declaration` are **independent concepts** that co-exist as separate top-level
fields and never imply one another. `merge_constraints` controls **causal ordering/prerequisite**
mechanics (must this cause's own event record apply before the effect, contributing to
`P_causation`/`P_global`). `causal_state_dependency_declaration` controls **apply-time state/input-
scope classification** (must this cause's own payload be inside the Input Contract's apply set/cursor
universe). An Event Contract may declare a `merge_constraints.prerequisite_policy` uniformly for all
non-empty `causation_refs` while this field separately classifies each entry's scope/visibility — one
field's value is never derived from, or substituted for, the other's.

### 9. Fail-closed rules — normative, no permissive fallback

No branch below resolves an ambiguous, missing, or malformed case permissively.

1. **Absence of `causal_state_dependency_declaration` — three distinguished cases (fixes
   `ADR048-A-MAJ-01`), never one unconditional rule:**
   - **(A) General Event Contract validity:** a pre-ADR-048 Published Event Contract version lacking
     this field is **not** globally invalid merely because the field is absent — its validity as an
     Event Contract version-artifact remains governed entirely by `ADR-039`'s own authority, unaffected
     by this ADR (see *Non-retroactivity* below).
   - **(B) Eligibility for `declared-state-dependencies` authority:** whenever an Input Contract
     declares `causal_closure_policy.mode: declared-state-dependencies` / `dependency_authority:
     per_effect_event_contract`, an effect event's pinned Event Contract version MUST contain a valid
     canonical declaration. If absent, that Event Contract version is **INELIGIBLE** to serve as the
     `per_effect_event_contract` dependency authority for that run — resolution fails closed **for
     that purpose only**, exactly as Chapter 8 §8.2.3 already requires when a declaration is absent.
     Processor code MUST NOT fill the gap.
   - **(C) Prospective authoring defect:** for a new Event Contract version explicitly intended to
     serve this authority mode after `ADR-048`'s approval, absence of the declaration is an
     authoring defect — Review A must reject that claimed capability before `Published`. This is
     **not** a claim that every future Event Contract universally requires the field — only contracts
     intended to serve `declared-state-dependencies` authority do.
2. Invalid or missing `mode` — integrity violation, reject.
3. `mode: vacuous` with non-empty `causation_refs` — integrity violation, reject.
4. `mode: vacuous` with `roles` present at all — malformed declaration, reject.
5. `mode: exhaustive` with `roles` missing, empty, or structurally malformed (a role missing
   `role_id`/`selector`/`cardinality`/`classification`, or a malformed `cardinality` per §5) —
   malformed declaration, reject.
6. Zero role matches for a `causation_refs` entry (`|matches(c)| = 0`) — integrity violation,
   unclaimed, reject.
7. More than one role matches for a `causation_refs` entry (`|matches(c)| > 1`) — integrity
   violation, ambiguous, reject — including when an overlapping role is itself optional.
8. Role cardinality unsatisfied (`|M(r)|` outside the role's declared bound) — integrity violation,
   reject.
9. Malformed `payload_field` path (references a path absent from `payload_shape`) — authoring-time
   defect, Review A must reject before `Published`.
10. A `payload_field` role whose path is declared optional in `payload_shape` legitimately resolving
    to zero refs for a given instance is **not** a failure, only when the role's own `cardinality`
    permits zero — distinguished from item 8, which fires only when the actual count falls outside the
    declared bound.
11. A `payload_field`-derived ref absent from the envelope's own `causation_refs` — integrity
    violation, reject.
12. A `by_target` selector's resolved target failing Chapter 8 §8.2.3 tuple consistency — the
    pre-existing, already-Locked fail-closed rule applies unchanged; this Decision weakens nothing.
13. A malformed static `by_target.match` (neither `event_types` nor `contract_ids` present) —
    authoring-time defect, Review A must reject before `Published`.
14. A `discriminant` field missing or unresolvable on the effect's own payload — integrity violation,
    reject.
15. A resolved discriminant value absent from `cases` — integrity violation, reject — no implicit/
    default case.
16. A target satisfying only part of a declared `event_types`/`contract_ids` conjunction is **not
    itself a failure** — the target is simply excluded from that role's match set; it may still belong
    to another role, or (if it belongs to none) trigger item 6 at Phase 2. Recorded only to
    distinguish ordinary non-match from an integrity violation.
17. A malformed `cardinality` declaration (any of the rejected forms in §5) — authoring-time defect,
    Review A must reject before `Published`.
18. **A duplicate `role_id` within one Event Contract version-artifact** — malformed declaration,
    reject (fixed here as an explicit addition to the reviewed v0.3 set: uniqueness of `role_id` is a
    precondition for the Phase-2 `matches(c)` computation to be unambiguous about *which* role a match
    belongs to, and must therefore be enforced as its own named failure mode).
19. **A duplicate canonical locator `(stream_id, sequence)` within one effect event's own
    `envelope.causation_refs`** (fixes `ADR048-A-MAJ-02`) — integrity violation, reject, regardless of
    whether the two entries' `event_id` values are equal or differ (a differing `event_id` at the same
    locator independently fails Chapter 8 §8.2.3's tuple-consistency invariant first). This precondition
    is validated before Phase 1 — see §6's uniqueness precondition above; `C` denotes the collection
    after this validation succeeds.

## Non-retroactivity and existing Published Event Contracts (required section)

This Decision does **not** declare any existing immutable Published Event Contract version-artifact
retroactively invalid.

1. **Existing Published Event Contract versions remain valid, immutable historical artifacts under
   the authority effective when they were Published.** `feature-computed/v1.0` and
   `feature-fact-invalidated/v1.0` (both Published, immutable) predate this ADR and currently carry no
   `causal_state_dependency_declaration` field — this does not retroactively invalidate them.
2. **This Decision applies prospectively** — to new Event Contract version-artifacts authored after
   ADR-048's approval, where the artifact is intended to serve as the `dependency_authority:
   per_effect_event_contract` authority for an Input Contract declaring `mode:
   declared-state-dependencies`.
3. **A Published Event Contract version lacking this canonical declaration MUST NOT be used as the
   per-effect state-dependency authority** for such a run/Input Contract — resolution must fail closed
   for that purpose, exactly as Chapter 8 §8.2.3 already requires when a declaration is absent.
4. **Processor code is never permitted to fill the missing classification** — the same prohibition
   Chapter 8 §8.2.3 already states, unweakened by this Decision.
5. **An existing immutable Event Contract version requiring this capability must receive a NEW
   version-artifact**, authored and reviewed under `ADR-039`'s own versioning/publication discipline
   and Chapter 10's compatibility rules. This ADR does **not** decide Feature's new version number,
   does **not** modify `feature-computed/v1.0` or `feature-fact-invalidated/v1.0`, and does **not**
   classify the compatibility of that future version delta — that is separate, later, governed work.

**First-publication Candle/Structure/Regime consequence:** the eight not-yet-Published Candle/
Structure/Regime Event Contracts may incorporate this field directly into their first `v1.0` snapshots
after this ADR's approval — no migration is required for an unpublished Draft candidate. The two
existing Candle Draft candidates remain `Draft` and are **not** remediated by this transaction; they
may be corrected in place before publication, in a separate, later WP.

## Candle examples (illustrative, representability evidence only — not applied to any file)

```yaml
# candle-closed/v1.0 — illustrative only
causal_state_dependency_declaration:
  mode: vacuous
```

```yaml
# candle-corrected/v1.0 — illustrative only
causal_state_dependency_declaration:
  mode: exhaustive
  roles:
    - role_id: corrected_fact
      selector:
        kind: by_target
        match:
          event_types: [CANDLE_CLOSED, CANDLE_CORRECTED]
          contract_ids: [candle-closed, candle-corrected]
      cardinality:
        exactly: 1
      classification: EXTERNAL_NON_STATE_CAUSE
      apply_time_requirement: >
        Authoritative application does not require re-reading the corrected predecessor's domain
        payload/state; the effect carries the complete replacement OHLCV/state itself; the
        predecessor reference is required only for identity/existence/lineage/causal precedence.
```

## Alternatives considered

**A. Top-level machine-readable declaration + explicit per-cause rule table (chosen).** Satisfies
Chapter 8 §8.2.3's requirement and prohibition with a self-contained, versioned, immutable-at-
publication field (fits `ADR-039`'s own model) and a closed, deterministic, order-independent
algorithm — see Decision above.

**B. Freeform/nested declaration under `payload_semantics_and_invariants`.** Rejected — not machine-
canonical: `payload_semantics_and_invariants` is a narrative/prose field with no authority-defined
schema for anything nested inside it, and any such nesting has no formal, reliable linkage back to a
specific `causation_refs` array entry.

**C. Classification inside `merge_constraints`.** Rejected — conflates two distinct Chapter 8
concepts: `merge_constraints` (§8.3.4) governs causal **ordering**; this Decision's subject governs
apply-time **state/input-scope** classification (§8.2.3). Forcing one field to carry both would either
corrupt a truthfully-empty `merge_constraints: {}` for a root event, or couple two independently-
versioned concepts' schema evolution together.

**D. Declare `STATE_DEPENDENCY` only, default everything else to `EXTERNAL_NON_STATE_CAUSE`.**
Rejected — an omitted, genuinely new causal role would be silently treated as external by default:
fail-**open**, not fail-closed. Absence of a declaration must never become a classification by
omission.

**E. Classification lives in processor/runtime code.** Rejected — directly prohibited by Chapter 8
§8.2.3's own text, and would let classification semantics change across deployments without changing
the pinned, immutable Event Contract — the exact replay/audit-integrity failure Chapter 8 §8.1.1
exists to prevent.

**F. Rely on `mode: full` causal closure only; do not implement a `declared-state-dependencies`
representation at all.** Rejected as this ADR's solution — not because `mode: full` is itself invalid
(Chapter 8 permits it for Input Contracts that choose it), but because Chapter 8 deliberately offers
`declared-state-dependencies` specifically to avoid unnecessarily expanding every Input Contract's
scope to every transitively-reachable `causation_ref`. This ADR implements an already-selected
constitutional mode; it does not argue for deleting or avoiding it. None of these alternatives are
claimed impossible in every conceivable architecture — each is rejected because it fails to satisfy
Chapter 8 and `ADR-039`'s own current, already-Locked authority for this platform.

**Consequences:**

Benefits:
- A generic validator can deterministically obtain classification from the pinned Event Contract
  artifact alone — no event-type-specific processor code anywhere.
- Immutable, replay/audit-stable semantics: once `Published`, a version's declaration never changes
  meaning.
- Explicit fail-closed completeness — no causation_ref can ever go silently unclassified or
  ambiguously double-classified.
- Supports root (`vacuous`), single-cause, multi-cause, optional-cause, and mixed state/external
  events within one uniform grammar.
- Role declaration order is semantically irrelevant, eliminating an entire class of authoring-order
  defects.

Costs:
- Larger Event Contract schema surface for every version intended to serve
  `dependency_authority: per_effect_event_contract`.
- Every such version must author and pass Review A for a complete, closed declaration — there is no
  partial/incremental declaration mode.
- Future selector/grammar evolution beyond `payload_field`/`by_target` would require its own governed
  architecture decision, not a silent extension.
- Existing Published Event Contract versions lacking this field cannot serve this authority mode until
  a new version-artifact is authored (§ Non-retroactivity above) — a real, bounded migration cost.

This ADR does **not** authorize Event Contract publication or Context Input Contract publication by
itself — those remain separate, later governed decisions.

**Risks:**

- Over-complex selector grammar for a future causal pattern not yet seen — mitigated by the closed
  tagged-union design (exactly two selector kinds, exactly two cardinality forms, exactly two
  declaration modes) and by requiring any future extension to go through its own governed decision
  rather than silent interpretation.
- Selector overlap or declaration defects — mitigated by the Phase-2 exactly-one-match rule and the
  explicit non-legalization of overlap by role optionality.
- Event-Contract-version migration burden for existing Published artifacts — mitigated by the
  Non-retroactivity section's explicit, bounded treatment (new version required, old version remains
  valid for its own historical scope).
- Malformed cardinality declarations — mitigated by the closed two-form union and explicit prohibited-
  combinations list.
- Future causal patterns not expressible by the current two selector kinds — mitigated by treating
  that as a signal for a new governed architecture decision, never a reason to silently extend this
  one's grammar.
- Immutable-version migration cost compounding across many contract_ids over time — mitigated by this
  Decision applying prospectively only, and by Structure/Regime/Feature's own first-publication or
  next-version authoring each independently absorbing the cost once, not retroactively.
