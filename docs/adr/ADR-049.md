## Context

`docs/domain/structure.md` §10's own "Deduplicate cascade" paragraph (verbatim):

> *"nếu cả một `SwingInvalidated` VÀ một `CandleCorrected` trực tiếp cùng ảnh hưởng một
> `BreakOfStructureDetected`/`ChangeOfCharacterDetected` (trường hợp hiếm — cùng một correction
> gốc lan tới cả hai đường), chỉ phát **một** `StructureFactInvalidated` cho fact đó —
> `causation_refs` liệt kê đủ cả hai nguyên nhân dưới dạng nhiều phần tử, `invalidation_cause`
> chọn nguyên nhân **trực tiếp nhất tại chính broken_swing_ref/breaking_candle_refs của fact đang
> bị invalidate**."*

This text names the selection criterion ("most direct at the fact's own `broken_swing_ref`/
`breaking_candle_refs`") but does not reduce it to a mechanically closed rule a producer or
validator can apply without further judgment. The ambiguity: `SwingInvalidated` is, from the
invalidated fact's own point of view, exactly as "direct" at `broken_swing_ref` as `CandleCorrected`
is at `breaking_candle_refs` — each is a zero-hop relationship to its own corresponding reference
type. §10's text supplies no tie-break between these two reference types themselves. A plausible
resolution — that `SwingInvalidated` relevant to this cascade is itself always caused by an
upstream `CandleCorrected`, making the Candle-side cause causally nearer to any shared root — is
**not verifiable from this ADR's in-scope authority**: `structure.md` §10's own nhánh (a)
describes *one* path by which this can happen, but does not state it as the *only* path, and
`swing.md` (which would own any general statement about every possible `SwingInvalidated` cause)
is outside this ADR's authority closure set. Treating that premise as already-proven would be
exactly the "pretend the rule already exists" error this ADR must not repeat.

**Representation question — already resolved, not reopened here.** Whether `causal_state_
dependency_declaration` can represent one-or-two simultaneous direct-cause entries is already
mechanically answered by Approved `ADR-048`: a static `by_target.match` selector tests every
`causation_refs` entry against one fixed `event_types`/`contract_ids` allow-set, independent of
any payload field, so both direct-cause entries (when both are present) fall into one role's match
set; only `cardinality` needs widening from Form A `{exactly: 1}` to Form B `{min: 1, max: 2}` —
both forms already part of `ADR-048`'s own closed grammar (§4 static `match`; §5 Form B range). No
`ADR-048` amendment, no new selector kind, no new cardinality form. This is correct application of
already-Approved architecture, not a decision this ADR makes.

**Ground truth, independently confirmed this transaction:** `docs/adr/ADR-048.md` (Approved, v0.3)
— static `match`/`discriminant` selector forms and Form A/B cardinality are its only closed
grammar; neither grammar element nor any amendment to it is required for the representation
question above. `docs/constitution/00-governance.md` §4b — the `ADR Required` trigger list contains

## Decision question

When `structure-fact-invalidated`'s rare dual-direct-cause case applies — `causation_refs` contains
both a matching `SwingInvalidated` and a matching `CandleCorrected` as direct causes for the same
invalidated `BreakOfStructureDetected`/`ChangeOfCharacterDetected` fact — what deterministic rule
selects the single scalar value of `payload.invalidation_cause`?

## Smallest coherent decision surface

This ADR decides **only** that one scalar-selection rule, for **only** the cascade's direct
ancestor (the first `StructureFactInvalidated` in a cascade). It does not decide, and leaves
unchanged:

- the `causal_state_dependency_declaration` representation (already resolved, see Context);
- the three-value `invalidation_cause` enum (`swing_invalidated`, `breaking_candle_corrected`,
  `chained_invalidation` — unchanged, no new value minted);
- `causation_refs`' role as the complete evidence set (both direct causes remain listed there
  regardless of which one the scalar names as primary);
- `chained_invalidation`'s own semantics — a `chained_invalidation`-caused fact depends, by the
  dependency-forward chain's own linear construction (`structure.md` §10,
  `E(k+1).prior_orientation = E(k).new_orientation`), on exactly ONE immediately-preceding fact,
  never two; the dual-cause case this ADR resolves never arises for it, and this ADR does not
  change that.

## Alternatives considered

1. **Causal-distance heuristic — `breaking_candle_corrected` wins because every relevant
   `SwingInvalidated` is itself always caused by an upstream `CandleCorrected`, making the
   Candle-side cause causally nearer.** Considered, but its own premise (every `SwingInvalidated`
   relevant to this cascade is always Candle-originated) is not provable from this ADR's authority
   closure set — `swing.md` is out of scope here, and `structure.md` §10 illustrates one path, not
   an exhaustive one. Not rejected as wrong, but rejected as a basis **this ADR cannot honestly
   claim as already-proven** — adopting it under this framing would repeat exactly the error this
   ADR exists to avoid.
2. **Fixed priority — `breaking_candle_corrected` always wins (CHOSEN, see Decision below),
   grounded instead in `structure.md`'s own declared Domain Contract chain ("Candle → Swing →
   Structure," `structure.md` line 17) rather than a per-instance causal-hop proof.** Candle is,
   by this repository's own already-established domain layering, the more fundamental upstream
   authority relative to Swing — Swing is itself always derived from Candle evidence in this
   pipeline. Choosing the Candle-domain cause as primary when both are present is consistent with,
   and a reasonable operational closure of, `structure.md` §10's own "most direct" language,
   without requiring an unprovable universal causal-distance claim.
3. **Fixed priority — `swing_invalidated` always wins.** Rejected: no principled basis favors the
   Swing-side cause as more direct; Swing is itself always a derived, downstream fact relative to
   Candle in this platform's own stated chain, making this alternative backward relative to the
   platform's own layering intuition that motivated Alternative 2.
4. **Leave the rule undetermined (producer discretion, no ADR rule).** Rejected: an
   undetermined scalar value would make this event's own payload non-reproducible across
   execution modes for an otherwise-identical input set, contradicting Chapter 8 §8.3.4's
   deterministic-application-order requirement and I-1 Explainability (an audit trail must be able
   to explain *why* a specific value was recorded, which a discretionary rule cannot answer).
5. **Replace scalar `invalidation_cause` with a multi-valued representation so no priority rule is
   needed.** Rejected per the task's own preservation requirement and on independent merit:
   `causation_refs`' own widened-cardinality role (already resolved, see Context) already carries
   complete dual-cause evidence; a multi-valued scalar would duplicate that evidence for zero
   additional explainability or determinism gain, and would itself be a payload-shape/Event-Schema
   change with a strictly larger blast radius than fixing a selection rule for an existing scalar.

## Decision

**`payload.invalidation_cause` MUST be `breaking_candle_corrected`** whenever
`structure-fact-invalidated`'s `causation_refs` contains both a matching `SwingInvalidated` and a
matching `CandleCorrected` as direct causes for the same invalidated fact (`structure.md` §10's
rare dual-direct-cause case, applying only to a cascade's direct ancestor — never to a
`chained_invalidation`-caused descendant, which never has two direct causes).

This is this ADR's **own new decision** — not a rule already mechanically present in
`structure.md`'s text. It is grounded in `structure.md`'s own declared domain chain ("Candle →
Swing → Structure"), which already establishes Candle as the more fundamental upstream authority
relative to Swing within this exact Domain Contract's stated model, giving a principled, in-scope,
repository-grounded operational closure of §10's own "most direct at
`broken_swing_ref`/`breaking_candle_refs`" instruction — not a claim that every instance's
causal-hop distance has been individually proven.

**Semantics:**

- When only one direct cause is present, `payload.invalidation_cause` selects exactly that cause
  (`swing_invalidated`, `breaking_candle_corrected`, or `chained_invalidation`) — this Decision only
  disambiguates the rare simultaneous two-direct-cause instance.
- `causation_refs` remains the complete evidence set regardless of which cause the scalar names —
  both direct-cause entries remain present and traceable (I-1 Explainability) even though the
  scalar names only one as primary.
- The rule is static and instance-independent: it does not require resolving, per occurrence,
  which cause is "closer" to a shared root — it fixes the answer platform-wide for this one
  recognized rare shape, satisfying determinism (Chapter 8 §8.3.4) and reproducibility across
  execution modes without per-instance judgment.
- `payload.invalidation_cause` remains a required scalar enum with its existing three values,
  unchanged in type/cardinality — no new enum value, no schema change.

**Consequences:**

- A follow-on, separately-governed bounded correction to `structure-fact-invalidated/v1.0.yaml`'s
  own `payload_semantics_and_invariants` (outside this ADR's file scope) must inline this exact
  rule as the authority for its `dual_cause_primary_selection` content, replacing any prior text
  that treated this selection as already mechanically derivable from `structure.md` alone — that
  prior text overclaimed; this ADR is now the correct citation.
- `ADR-048` remains untouched, Approved, v0.3 — no amendment, no supersession.
- No Event Contract is authored, corrected, reviewed, or published by this ADR.
- This Decision is prospective only — it governs future authoring of
  `structure-fact-invalidated`'s own content; it does not retroactively alter any already-existing
  file (none currently correctly cites this rule as ADR-sourced authority).
