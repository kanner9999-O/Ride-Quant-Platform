## Decision — representation question and resolution

**Question:** does Approved `ADR-048`'s existing closed grammar already represent
`StructureFactInvalidated`'s rare legitimate dual-direct-cause case without amendment, and if so, how?

**Answer: YES.** Tested explicitly against `ADR-048` §4/§5/§6 (static `by_target` `match` selector +
Form B range cardinality + the two-phase matching algorithm):

Replace the current **discriminated** `invalidation_cause_ref` role (`kind: by_target`,
`discriminant.payload_path: [invalidation_cause]`, `cardinality: {exactly: 1}`) with a single
**static-match** `direct_cause_ref` role:

```yaml
- role_id: direct_cause_ref
  selector:
    kind: by_target
    match:
      event_types: [SWING_INVALIDATED, CANDLE_CORRECTED, STRUCTURE_FACT_INVALIDATED]
      contract_ids: [swing-invalidated, candle-corrected, structure-fact-invalidated]
  cardinality:
    min: 1
    max: 2
  classification: EXTERNAL_NON_STATE_CAUSE
```

held alongside the unchanged `invalidated_fact_ref` role (`payload_field`, `exactly: 1`,
`EXTERNAL_NON_STATE_CAUSE`).

**Why the discriminated form cannot represent the dual-cause case at all (any cardinality):** the
discriminated selector resolves `discriminant.payload_path` (`invalidation_cause`, a single scalar
enum token) to exactly ONE `cases` entry per event; only that one case's allow-set contributes to the
role's match set `M(r)` for this event instance. In the rare dual-cause case, `payload.invalidation_cause`
still holds exactly one value (the selected primary cause), so the discriminant activates only one
case's allow-set — the OTHER direct-cause entry in `causation_refs` (a different event type) matches
no case, hence `|matches(c)| = 0` for it under `ADR-048` §6 Phase 2 → **fail closed**, regardless of
any cardinality value chosen. This is a structural property of the discriminated form, not a
cardinality defect — raising `cardinality` on a discriminated role cannot fix it. The static `match`
form has no such dependency: it tests every `causation_refs` entry against one fixed allow-set,
independent of any payload field, so both direct-cause entries (when both are present) fall into the
same role's match set and only `cardinality` needs to widen from `exactly: 1` to `{min: 1, max: 2}`.

**Phase-2 exactly-one-role-match still holds for every entry:** `invalidated_fact_ref`'s target
(the BOS/CHoCH being invalidated) is never `SWING_INVALIDATED`/`CANDLE_CORRECTED`/
`STRUCTURE_FACT_INVALIDATED`-typed, so it never falls into `direct_cause_ref`'s match set; conversely
no direct-cause entry is the payload-declared `invalidated_fact_ref` value. The two roles' match sets
are disjoint by construction for every real instance (1-cause or 2-cause) — Phase 2 validates cleanly
in both cases with no overlap and no new Phase-2 relaxation.

**No `ADR-048` amendment is needed.** Both grammar elements used (static `match` selector, Form B
range cardinality) are already part of `ADR-048`'s existing closed grammar; this ADR applies that
grammar, it does not extend it. `ADR-048` itself is untouched.

**`payload.invalidation_cause` scalar remains sufficient — no schema evolution.** It continues to
carry exactly one of the three existing enum values (`swing_invalidated`, `breaking_candle_corrected`,
`chained_invalidation`), naming the deterministically-selected PRIMARY cause. The scalar's job is
disambiguation-for-the-reader (which cause is primary), not evidence-completeness — evidence
completeness is now `causation_refs`' own job via the widened-cardinality `direct_cause_ref` role.
Alternative B (multi-valued `invalidation_cause`) is therefore unnecessary: it would duplicate
information the causation-ref role already carries, for zero evidentiary gain.

**Deterministic primary-cause selection rule.** `structure.md` §10 already states the selection
criterion verbatim: choose whichever direct cause is "most direct at the fact's own
`broken_swing_ref`/`breaking_candle_refs`" — i.e. a pure function of the invalidated fact's own fixed
structural references (it has exactly one `broken_swing_ref` per §6a, and a fixed
`breaking_candle_refs` set per §6) and each candidate cause's own relation to those specific
references. This is deterministic per occurrence (same inputs always produce the same single
answer) even though it is not reducible to one static global priority (e.g. "Candle always beats
Swing") independent of which fact is being invalidated. Resolving the exact tie-break predicate into
inlined, self-contained Event Contract prose (per `ADR-039`) is Structure-local Domain Contract
content already present in §10 — it belongs to the follow-on Event Contract correction WP, not to
this ADR, which governs representation only.

**Dual-cause scope is structurally bounded to the direct-ancestor branch.** §10's dual-cause paragraph
only applies to a cascade's **direct invalidated ancestor** (branches (a)/(b) in §10's own cascade
diagram) — a `chained_invalidation`-caused fact depends, by the dependency-forward chain's own linear
construction (`E(k+1).prior_orientation = E(k).new_orientation`), on exactly ONE immediately-preceding
fact, never two. The merged `direct_cause_ref` role's `{min: 1, max: 2}` cardinality is therefore
already correct for every real occurrence (always exactly 1 or exactly 2, never more) without needing
a second role to separate the `chained_invalidation` case out; the additional business constraint that
2 entries never occur together with a `chained_invalidation` cause is ordinary Event-Contract-local
invariant prose (same treatment as every other business rule `ADR-048`'s own grammar does not itself
encode), authored by the follow-on correction WP, not by this ADR.

## Alternatives considered

**A. Preserve full dual-cause evidence (causation_refs, widened-cardinality merged role) + deterministic
scalar primary cause via `structure.md` §10's own selection criterion, inlined by the follow-on
correction (chosen).** Smallest coherent correction: uses only already-Approved `ADR-048` grammar
elements (static `match`, Form B range cardinality), changes no other artifact, preserves full causal
evidence (I-1 Explainability — both causes remain traceable in `causation_refs`), does not reopen
`ADR-048`.

**B. Change `invalidation_cause` to a multi-valued representation (ordered/set-like cause collection).**
Rejected. Would be an Event Schema payload-shape change with migration/reader implications, but
`causation_refs`' own widened-cardinality role already carries full dual-cause evidence — a
multi-valued scalar would duplicate that evidence for no additional explainability or determinism
gain, violating the smallest-coherent-correction requirement.

**C. Collapse to exactly one direct cause (remove the §10 dual-cause semantic) — CORR-001's own prior
correction.** Rejected. This is the error this ADR exists to correct: it discards real, explicit
Domain Contract authority (§10) that CORR-001 missed by checking only §5, and it loses causal evidence
for the rare case against I-1 Explainability. Not selected merely because it is the current Draft
Event Contract's state — the current state is exactly what is wrong.

**D. Extend `ADR-048`'s selector/cardinality grammar for this case.** Rejected. Not needed: the
explicit test above (static `match` selector + Form B range cardinality, both already part of
`ADR-048`'s existing closed grammar) fully represents the required semantics. Broadening already-
Approved platform architecture for a Structure-local representation problem, when existing grammar
already suffices, is unnecessary scope expansion. `ADR-048` is untouched by this ADR.
