## Problem

A Quality Gate whose raw score depends on a mutant population containing
one or more permanently-unresolved classifications has no existing,
repository-authoritative rule for producing a PASS/FAIL/STOP verdict. Two
naive resolutions are both wrong: (a) silently excluding unresolved mutants
from the population would change the denominator without governed
authority and would quietly discard exactly the disagreement the protocol
was designed to surface; (b) waiting indefinitely for the disagreement to
resolve blocks the gate even in cases where the disagreement is
*mathematically irrelevant* to the verdict (i.e., the gate would FAIL or
PASS identically regardless of how the unresolved mutants eventually
classify). Chapter 13 §13.10 (Locked) governs ordinary test-suite flakiness
— a *test* producing an unstable pass/fail on unchanged code — and is
relevant context but does not define how a mutation-evaluation
classification disagreement (`timeout ↔ killed`, an infrastructure-level
per-mutant outcome) should be formally consumed by a gate's score. No other
existing repository authority (Testing Convention v0.17 item 8's
deterministic-reproduction-before-credit rule) supplies this either — it
requires reproduction before credit, but does not define gate behavior when
reproduction itself disagrees. This is a genuine authority gap:
`EXISTING_AUTHORITY_INSUFFICIENT`.

## Decision

**Bounded-Uncertainty Interpretation for Mutation Timeout Triage.** For a
mutation/test-effectiveness Quality Gate whose mutant population contains
`UNSTABLE_TIMEOUT_TRIAGE`-class unresolved mutants (per a closed,
structural applicability predicate), the gate computes a conservative
lower bound and a best-case upper bound on its score, granting the
unresolved mutants zero favorable credit in the lower bound and full
favorable credit in the upper bound, and derives a gate-level PASS / FAIL
/ STOPPED outcome from where the required threshold falls relative to that
bound — never by resolving, guessing, voting on, or retrying any
individual unresolved mutant's own classification.

**The complete, authoritative, executable specification of this rule —
applicability predicate, protocol-provenance requirements, the
per-mutant/gate-level reproducibility reconciliation, Testing Convention
item 8 precedence, the exact formula, and the Case A/B/C result semantics
— is Chapter 13 §13.8.1, and Chapter 13 §13.8.1 alone** (§13.13; see
"Relationship to Chapter 13 §13.13" and "Clause-trace table" below). This
document does not restate that specification a second time; every
guarantee below is a summary/rationale statement that resolves, via the
clause-trace table, to its exact normative Chapter 13 clause.

## Architectural invariants

These are the guarantees this decision commits to — stated here as goals
this ADR's rationale defends; their exact executable text lives in
Chapter 13 §13.8.1 (see "Clause-trace table"):

- **Never resolve an unresolved mutant.** No majority vote, no N-of-M
  voting, no arbitrary third-run tie-break, no retry-until-green — an
  `UNSTABLE_TIMEOUT_TRIAGE` mutant's own classification is never guessed,
  in any outcome.
- **Two distinct reproducibility layers.** A mutant's own per-mutant
  classification remaining unresolved is a separate question from
  whether the *gate-level bounded interval* is itself a deterministic,
  reproducible function of pinned inputs — both must hold, and neither
  substitutes for the other.
- **PASS never relies on unresolved evidence.** A gate-level `PASS` is
  authorized only when the threshold is met granting zero credit to any
  unresolved mutant.
- **FAIL requires certainty.** A gate-level `FAIL — criteria` is
  authorized only when no possible resolution of the unresolved mutants
  could reach the threshold.
- **Genuine indeterminacy stops, it does not guess.** When the threshold
  falls inside the bound, no final PASS/FAIL is emitted — the evaluation
  remains an incomplete, fail-closed state, not a fourth kind of final
  result.
- **Closed, narrow applicability.** Only the exact governed
  `UNSTABLE_TIMEOUT_TRIAGE` classification, produced by a procedure
  meeting explicit structural properties, may enter the mechanism — never
  a general "unresolved/ambiguous mutant" rule, and never a self-declared
  "equivalent" protocol.
- **Non-scoped defects are never laundered.** A separate, non-scoped
  evidence defect in the same population must be dispositioned on its own
  authority; this rule's own outcome never masks it.
- **No new metric, no denominator change.** The rule reuses the gate's
  own already-authoritative metric/denominator/threshold exactly.
- **Single normative source.** This rule's executable text exists in
  exactly one place (Chapter 13 §13.8.1) — this ADR never carries a
  second, independently-executable copy.

## Relationship to Chapter 13 §13.10

Chapter 13 §13.10 (Locked) is explicitly preserved, not redefined, by this
decision:

- retry-until-green remains prohibited — this decision computes bounds
  from the reproductions already produced by the current Feature Engine
  procedure satisfying §13.8.1; it never triggers an
  additional run to change a mutant's classification;
- unstable evidence is never credited as passing evidence — the lower
  bound (which alone can produce a `PASS`) grants unresolved mutants zero
  credit, satisfying §13.10's rule directly;
- a specific *test* is quarantined only when evidence establishes that
  **that test itself** is flaky/timing-dependent on unchanged code —
  §13.10's own trigger, unchanged;
- mutation-evaluation classification instability (a mutmut-level, per
  mutant timeout-detection disagreement on *mutated* code) does NOT, by
  itself, automatically quarantine any test covering the unstable mutant.
  `FE-EVID03-COND1-STOP-001` found the 9 current unstable mutants' covering
  tests pass reliably and quickly (0.26s, uncontended) against unmutated
  code — there is no evidence any of those tests are themselves flaky under
  §13.10's own definition.
- Test-level quarantine (§13.10) and mutation-classification uncertainty
  (this ADR) are governed as **distinct concerns** with distinct triggers;
  this decision creates no automatic bridge from one to the other in
  either direction.

This ADR is a **gate-interpretation mechanism**, not a test-flakiness
labeling mechanism, and does not touch, extend, or narrow §13.10's own
quarantine trigger or evidence rule.

## Alternatives considered

1. **Permanent STOP on any disagreement, indefinitely.** Rejected as the
   sole rule — it is exactly today's un-augmented state, and blocks the
   gate even in cases (like the current one) where the disagreement is
   provably irrelevant to the outcome. Case C of the chosen candidate
   preserves this behavior exactly when — and only when — the disagreement
   genuinely could change the result.
2. **Majority vote / third-run tie-break.** Rejected — directly
   contradicted by Chapter 13 §13.8.1's structural Protocol provenance
   requirements' own "no majority vote, no guess" clause and by
   Chapter 13 §13.10's retry-until-green prohibition; would silently
   manufacture a status for a mutant those requirements deliberately
   leave unresolved.
3. **Treat all unstable as survived (maximally conservative).** Equivalent
   to using `lower_score` alone as a single point estimate for the final
   verdict — so it agrees with the chosen candidate whenever `lower_score
   ≥ T` (both would PASS) or `upper_score < T` (both would FAIL, as in the
   current EVID-03 case). Its actual defect is confined to the straddle
   region: when `lower_score < T ≤ upper_score`, this alternative would
   force a `FAIL` (since its own single point estimate, `lower_score`, is
   below `T`), while the correct bounded interpretation must `STOP —
   UNRESOLVED`, because the unresolved mutants can still change the
   verdict in that region and a forced FAIL would misstate genuine
   uncertainty as a certain criteria-failure. Rejected for this
   straddle-region defect — not for the reason v0.1 of this document
   incorrectly stated (corrected per `MINOR-01`).
4. **Treat all unstable as killed (maximally optimistic).** Rejected —
   this is precisely the ungoverned credit-without-evidence Testing
   Convention item 8 and Chapter 13 §13.10 both exist to prevent; it would
   allow an unresolved mutant to silently pass a gate.
5. **Test quarantine alone (apply §13.10 mechanically to covering tests).**
   Rejected as the sole mechanism — §13.10 quarantines a *test* found to be
   individually flaky; the 9 current unstable mutants' covering tests show
   no such evidence (fast, reliable, uncontended). Quarantining tests that
   are not shown to be flaky, merely because they cover an
   unstable-classified mutant, would misapply §13.10's own trigger and
   could suppress genuine future mutation-detection coverage.
6. **Bounded uncertainty / interval interpretation (CHOSEN).** Computes
   both bounds from the *existing*, unchanged protocol output; never
   credits an unresolved mutant; permits PASS only when uncredited
   evidence already suffices; permits FAIL only when no possible resolution
   changes the outcome; STOPs only when the outcome is genuinely
   undetermined. Strictly the narrowest rule that resolves the authority
   gap without inventing new per-mutant resolution machinery.

No alternative other than the bounded-uncertainty candidate is endorsed;
no fresh repository authority was found that contradicts or forecloses it.

one-off evidence correction, while remaining narrowly bounded rather than
open-ended.

## Failure modes

- **Silent scope creep to non-timeout uncertainty.** This rule is
  narrowly scoped to `UNSTABLE_TIMEOUT_TRIAGE`-class disagreements produced
  by a procedure satisfying Chapter 13 §13.8.1's structural Protocol
  provenance requirements. It must not be read as authorizing
  bounded-uncertainty treatment for any other kind of unresolved or
  ambiguous mutant status (e.g. Condition-2's own, separately-governed
  `AMBIGUOUS — EVIDENCE INSUFFICIENT`/`TOOL_IDENTITY_DRIFT` categories,
  which this ADR does not touch).
- **Threshold gaming via denominator manipulation.** Guarded against by
  Chapter 13 §13.8.1's own explicit requirement (Formal bound definitions)
  to reuse the gate's own already-authoritative denominator unchanged —
  this rule supplies no mechanism to alter it.
- **Case C used as a permanent escape hatch.** If a future population
  persistently straddles `T` across repeated measurements, that is a
  signal for separate, future governed work (e.g., root-cause remediation
  of the instability itself, per `FE-EVID03-COND1-STOP-001`'s own
  recommendation) — this ADR does not define a time limit or automatic
  escalation for a persistent Case C; that is intentionally left to
  ordinary Product Owner/architecture judgment, not hard-coded here.
