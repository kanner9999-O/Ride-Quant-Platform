## Context

`docs/governance/mutation-baseline-evidence/feature-engine-mutation-step9-formal-evidence-005.json`'s
locked timeout-triage protocol runs each raw-timeout mutant candidate
through two independent, freshly-regenerated, isolated single-worker
reproductions and classifies the outcome deterministically: timeout+timeout
→ `confirmed_timeout`; killed+killed → resolved `killed`; survived+survived
→ resolved `survived`; any disagreement → `UNSTABLE_TIMEOUT_TRIAGE`, with an
explicit "no majority vote, no guess" rule. `evidence-005-correction-001.json`
(`P3-FEATURE-EVID03-STEP9-005-A-MAJ-01`, Review A validated) established
that this protocol's disagreement clause is a genuine STOP on Condition-1
gate interpretation — the protocol defines what happens *up to and
including* a disagreement, but not what a Quality Gate is authorized to
conclude *given* one or more permanently-unresolved mutants in the
population.

The completed bounded investigation `FE-EVID03-COND1-STOP-001`
(`docs/governance/mutation-baseline-evidence/feature-engine-condition1-unstable-timeout-investigation-001.json`,
Review A `CLEAN — 0/0/0`, Risk `R1`, `ADR_NOT_REQUIRED` for the
investigation itself) confirmed the exact 9 mutants currently in this
state, found them structurally confined to real-filesystem-I/O-touching
`authority_resolver.py` functions, and classified all 9
`REQUIRES_GOVERNED_PROTOCOL_DECISION` — evidence is complete and
consistent for all 9; the existing protocol simply does not define a next
step.

## Problem

A Quality Gate whose raw score depends on a mutant population containing
one or more permanently-unresolved classifications has no existing,
repository-authoritative rule for producing a PASS/FAIL/STOP verdict. Two
naive resolutions are both wrong: (a) silently excluding unresolved mutants
from the population would change the denominator without governed
authority and would quietly discard exactly the disagreement the protocol
was designed to surface; (b) waiting indefinitely for the disagreement to
resolve blocks the gate even in cases where the disagreement is
*mathematically irrelevant* to the verdict (i.e., the gate would FAIL or
PASS identically regardless of how the unresolved mutants eventually
classify). Chapter 13 §13.10 (Locked) governs ordinary test-suite flakiness
— a *test* producing an unstable pass/fail on unchanged code — and is
relevant context but does not define how a mutation-evaluation
classification disagreement (`timeout ↔ killed`, an infrastructure-level
per-mutant outcome) should be formally consumed by a gate's score. No other
existing repository authority (Testing Convention v0.17 item 8's
deterministic-reproduction-before-credit rule) supplies this either — it
requires reproduction before credit, but does not define gate behavior when
reproduction itself disagrees. This is a genuine authority gap:
`EXISTING_AUTHORITY_INSUFFICIENT`.

## Decision candidate

**Bounded-Uncertainty Interpretation for Mutation Timeout Triage.**

### 1. Preserve unstable classification

A mutant with conflicting qualifying timeout-triage reruns remains exactly
`UNSTABLE_TIMEOUT_TRIAGE`. This decision never resolves, guesses, or infers
whether such a mutant is killed, survived, or confirmed-timeout.
Specifically prohibited, permanently, for this class of disagreement:

- majority vote;
- 2-of-3 (or any N-of-M) voting;
- an arbitrary third-run tie-break;
- retry-until-green.

### 2. Formal bound definitions

For a mutation gate whose population contains `U` unresolved
`UNSTABLE_TIMEOUT_TRIAGE` mutants, reusing — never replacing — the
already-authoritative mutation metric for that gate (Testing Convention
v0.17 item 7's Ride-owned formula, `(killed + confirmed_timeout) / (total −
skipped) × 100`, and that gate's own already-established denominator):

```text
lower_numerator (conservative) = confirmed favorable numerator
  = killed + confirmed_timeout
  (the U unstable mutants are granted ZERO favorable credit)

upper_numerator (best-case)    = lower_numerator + U
  (the U unstable mutants are hypothetically ALL resolved favorably)

denominator                    = the gate's own already-authoritative
                                  denominator (total − skipped), unchanged

lower_score = lower_numerator / denominator × 100
upper_score = upper_numerator / denominator × 100
```

No new metric, formula, or denominator is introduced. `U` unresolved
mutants never silently leave the denominator; they remain counted, exactly
as today, simply without favorable credit in the lower bound and with full
favorable credit in the upper bound.

### 3. Gate interpretation — final results vs. evaluation state

Given the gate's already-approved required threshold `T`. **Cases A and B
are final Quality-Gate results** — the same `FAIL — criteria`/`PASS`
vocabulary Chapter 13 §13.9 already defines, unchanged, not extended.
**Case C is not a fourth final result — it is an evaluation state.** No
new entry is added to §13.9's existing `FAIL — criteria` / `FAIL —
evidence` / `PASS` taxonomy:

| Case | Condition | Outcome type | Result/state | Reason |
|---|---|---|---|---|
| A | `upper_score < T` | **Final result** | `FAIL — criteria` | No possible resolution of the unstable cases reaches `T`. Per-mutant uncertainty persists but is mathematically irrelevant to the verdict. |
| B | `lower_score ≥ T` | **Final result** | `PASS` | `T` is met granting the unstable cases zero credit — PASS never relies on unstable evidence. |
| C | `lower_score < T ≤ upper_score` | **Evaluation state (NOT a final result)** | `STOPPED / UNRESOLVED` | The unresolved classifications can still change the outcome. No `PASS`/`FAIL` is emitted. Gate eligibility remains incomplete and fail-closed (§13.1/§13.8's "Missing gate ≠ passed gate") — a downstream Approval Gate `PASS` prerequisite (Chapter 12 §12.2(5)) is not satisfied. Not relabeled `FAIL — evidence` either: the bounded interval itself may be complete, pinned, and reproducible (§13.9) — it simply does not yet determine a final criteria outcome. |

Cases A/B/C are exhaustive and mutually exclusive for any `U ≥ 0`
(`U = 0` collapses `lower_score = upper_score`, reducing to the ordinary
two-way PASS/FAIL the gate already used before this decision existed —
Case C becomes structurally unreachable, not merely rare).

**Resume/follow-up for Case C.** A later evaluation may reach a final
result (Case A or B) only after a separately governed action changes the
authoritative inputs relevant to the interval — e.g. legitimate
resolution/remediation of the underlying unresolved cases under an
authorized protocol, a new authoritative measurement/evidence boundary, or
other separately governed remediation. This decision does not prescribe
which specific mechanism applies to any given Case C — that is future,
separately governed work. It explicitly does not authorize, as a way out
of Case C: majority vote, N-of-M voting, an arbitrary third-run tie-break,
retry-until-green, or denominator manipulation — all remain prohibited
exactly as in Cases A/B (§1/§4).

### 4. Anti-gaming constraints

- This rule NEVER increases a gate's numerator by excluding, reclassifying,
  or silently resolving an unresolved mutant — `lower_numerator` and
  `upper_numerator` are the only two computed values, and both are strict
  functions of the *count* of unresolved mutants, never their guessed
  status.
- A `PASS` under Case B is valid only when it holds with **zero** credit
  granted to any unresolved mutant — a future implementer MUST NOT tune
  `U`'s treatment per-mutant to manufacture a `PASS`.
- This rule supplies no mechanism to reduce `U` other than the
  already-existing, unchanged two-run timeout-triage protocol itself
  (§5 below) — it is a **read-only interpretation layer** over that
  protocol's output, never a second, competing way to resolve a mutant's
  status.
- Case C (`STOPPED`) is the *conservative default* whenever both bounds
  straddle `T` — there is no "close enough" or discretionary override to
  Case A/B from Case C.

### 5. Reconciliation with Chapter 13 §13.8 (fail-closed semantics)

Chapter 13 §13.8 (Locked, v1.7) requires a gate to `FAIL` when
"measurement không reproducible." Read naively, an individually
unresolved `UNSTABLE_TIMEOUT_TRIAGE` mutant could seem to trigger this —
its own two-run classification genuinely did not reproduce. This decision
resolves that tension by distinguishing two separate reproducibility
questions, never conflating them:

- **Per-mutant reproducibility** — unchanged, governed exactly as §13.8
  already requires. An `UNSTABLE_TIMEOUT_TRIAGE` mutant's own
  killed/survived/confirmed-timeout classification remains unresolved.
  This decision NEVER asserts, implies, or treats that classification as
  having become reproducible, in any of Cases A/B/C.
- **Gate-level bounded-measurement reproducibility** — the *new* semantic
  this decision adds. When every input to §2's bound computation is
  immutable and pinned per §13.9 (confirmed-favorable numerator, `U`, the
  gate's own authoritative denominator, `T`, the exact criteria/policy
  version, and the evaluation boundary), the derived interval
  `[lower_score, upper_score]` is itself a deterministic, reproducible
  function of those pinned inputs — reproducible in exactly the sense
  §13.8/§13.9 require, even though the individual mutants inside `U`
  remain unresolved.

This is explicitly **not already authorized by Chapter 13 v1.7 as
written** — v1.7 has no concept of a gate-level bounded-measurement
interval distinct from per-mutant resolution. It is a genuinely new
Quality-Gate measurement semantic, which is exactly why this decision
requires both an ADR (this document, the architecture rationale) and a
separate Chapter 13 successor carrying the authoritative rule text (see
"Relationship to Chapter 13" and "Activation model" below) — never this
ADR alone.

Under this reconciliation: Case A (`FAIL — criteria`, a **final result**)
is authorized only when bounded measurement *proves*, with certainty, that
no resolution of the unstable cases reaches `T` — a genuine §13.8-style
criteria-failure, not a guess. Case B (`PASS`, a **final result**) never
relies on unresolved evidence. **Case C (`STOPPED / UNRESOLVED`) is not a
final result at all — it is an evaluation state**, the fail-closed outcome
whenever the interval straddles `T`: the bounded measurement itself can be
entirely valid, pinned, and reproducible, while the *threshold question*
remains genuinely undetermined by current evidence. This is consistent
with, not a weakening of, §13.8's own fail-closed philosophy and its
"Missing gate ≠ passed gate" principle — Case C leaves gate eligibility
incomplete, so a downstream Approval Gate `PASS` prerequisite (Chapter 12
§12.2(5)) is not satisfied, without asserting a criteria-failure that has
not been proven and without inventing a fourth entry in §13.9's existing
`FAIL — criteria` / `FAIL — evidence` / `PASS` result taxonomy.

## Relationship to Chapter 13 §13.10

Chapter 13 §13.10 (Locked) is explicitly preserved, not redefined, by this
decision:

- retry-until-green remains prohibited — this decision computes bounds
  from the *existing* two canonical protocol runs; it never triggers an
  additional run to change a mutant's classification;
- unstable evidence is never credited as passing evidence — the lower
  bound (which alone can produce a `PASS`) grants unresolved mutants zero
  credit, satisfying §13.10's rule directly;
- a specific *test* is quarantined only when evidence establishes that
  **that test itself** is flaky/timing-dependent on unchanged code —
  §13.10's own trigger, unchanged;
- mutation-evaluation classification instability (a mutmut-level, per
  mutant timeout-detection disagreement on *mutated* code) does NOT, by
  itself, automatically quarantine any test covering the unstable mutant.
  `FE-EVID03-COND1-STOP-001` found the 9 current unstable mutants' covering
  tests pass reliably and quickly (0.26s, uncontended) against unmutated
  code — there is no evidence any of those tests are themselves flaky under
  §13.10's own definition.
- Test-level quarantine (§13.10) and mutation-classification uncertainty
  (this ADR) are governed as **distinct concerns** with distinct triggers;
  this decision creates no automatic bridge from one to the other in
  either direction.

This ADR is a **gate-interpretation mechanism**, not a test-flakiness
labeling mechanism, and does not touch, extend, or narrow §13.10's own
quarantine trigger or evidence rule.

## Relationship to the existing locked timeout-triage protocol

The existing two-run protocol (`evidence-005.json` `timeout_triage.protocol`)
remains the sole, unchanged, authoritative mechanism for producing each
mutant's own classification: `confirmed_timeout`, `killed`, `survived`, or
`UNSTABLE_TIMEOUT_TRIAGE`. This decision does not alter, re-run, or
reinterpret any individual mutant's classification — it adds *only* the
previously-missing gate-level interpretation for a population that
*contains* one or more `UNSTABLE_TIMEOUT_TRIAGE` entries. No historical
evidence artifact is rewritten by this ADR: `evidence-005.json` and
`evidence-005-correction-001.json` remain byte-unchanged, and are not
modified by this ADR's approval, if it occurs.

## Alternatives considered

1. **Permanent STOP on any disagreement, indefinitely.** Rejected as the
   sole rule — it is exactly today's un-augmented state, and blocks the
   gate even in cases (like the current one) where the disagreement is
   provably irrelevant to the outcome. Case C of the chosen candidate
   preserves this behavior exactly when — and only when — the disagreement
   genuinely could change the result.
2. **Majority vote / third-run tie-break.** Rejected — directly
   contradicted by the already-Review-A-validated locked protocol's own
   "no majority vote, no guess" clause and by Chapter 13 §13.10's
   retry-until-green prohibition; would silently manufacture a status for
   a mutant the protocol deliberately left unresolved.
3. **Treat all unstable as survived (maximally conservative).** Equivalent
   to using `lower_score` alone as a single point estimate for the final
   verdict — so it agrees with the chosen candidate whenever `lower_score
   ≥ T` (both would PASS) or `upper_score < T` (both would FAIL, as in the
   current EVID-03 case). Its actual defect is confined to the straddle
   region: when `lower_score < T ≤ upper_score`, this alternative would
   force a `FAIL` (since its own single point estimate, `lower_score`, is
   below `T`), while the correct bounded interpretation must `STOP —
   UNRESOLVED`, because the unresolved mutants can still change the
   verdict in that region and a forced FAIL would misstate genuine
   uncertainty as a certain criteria-failure. Rejected for this
   straddle-region defect — not for the reason v0.1 of this document
   incorrectly stated (corrected per `MINOR-01`).
4. **Treat all unstable as killed (maximally optimistic).** Rejected —
   this is precisely the ungoverned credit-without-evidence Testing
   Convention item 8 and Chapter 13 §13.10 both exist to prevent; it would
   allow an unresolved mutant to silently pass a gate.
5. **Test quarantine alone (apply §13.10 mechanically to covering tests).**
   Rejected as the sole mechanism — §13.10 quarantines a *test* found to be
   individually flaky; the 9 current unstable mutants' covering tests show
   no such evidence (fast, reliable, uncontended). Quarantining tests that
   are not shown to be flaky, merely because they cover an
   unstable-classified mutant, would misapply §13.10's own trigger and
   could suppress genuine future mutation-detection coverage.
6. **Bounded uncertainty / interval interpretation (CHOSEN).** Computes
   both bounds from the *existing*, unchanged protocol output; never
   credits an unresolved mutant; permits PASS only when uncredited
   evidence already suffices; permits FAIL only when no possible resolution
   changes the outcome; STOPs only when the outcome is genuinely
   undetermined. Strictly the narrowest rule that resolves the authority
   gap without inventing new per-mutant resolution machinery.

No alternative other than the bounded-uncertainty candidate is endorsed;
no fresh repository authority was found that contradicts or forecloses it.

## Consequences

This ADR decides the interpretation rule/rationale only; the authoritative
measurement-rule text lives in the Chapter 13 successor (§13.8.1), per
"Relationship to Chapter 13 §13.13" above. It does not implement, apply, or
trigger a recomputation of any current Quality Gate result. **Only after
the full activation model completes** — this ADR Approved AND the Chapter
13 successor activated as the chapter's controlling version AND MANIFEST
updated accordingly (see "Activation model") — would a **separate,
subsequent, bounded transaction** be required to formally apply the rule
to current EVID-03 evidence and record the resulting Condition-1 verdict;
this ADR does not perform that application itself, and ADR approval alone
does not suffice to authorize it. This decision is reusable: once
activated, it applies to any Tier-1/Tier-0 mutation/test-effectiveness gate
that can produce `UNSTABLE_TIMEOUT_TRIAGE`-class unresolved mutants under
the same or an equivalently-governed timeout-triage protocol, not to
Feature Engine's EVID-03 alone — this is precisely why it is a governed,
reusable interpretation rule rather than a one-off evidence correction.

## Failure modes

- **Silent scope creep to non-timeout uncertainty.** This rule is
  narrowly scoped to `UNSTABLE_TIMEOUT_TRIAGE`-class disagreements produced
  by the existing locked protocol. It must not be read as authorizing
  bounded-uncertainty treatment for any other kind of unresolved or
  ambiguous mutant status (e.g. Condition-2's own, separately-governed
  `AMBIGUOUS — EVIDENCE INSUFFICIENT`/`TOOL_IDENTITY_DRIFT` categories,
  which this ADR does not touch).
- **Threshold gaming via denominator manipulation.** Guarded against by
  §2's explicit requirement to reuse the gate's own already-authoritative
  denominator unchanged — this rule supplies no mechanism to alter it.
- **Case C used as a permanent escape hatch.** If a future population
  persistently straddles `T` across repeated measurements, that is a
  signal for separate, future governed work (e.g., root-cause remediation
  of the instability itself, per `FE-EVID03-COND1-STOP-001`'s own
  recommendation) — this ADR does not define a time limit or automatic
