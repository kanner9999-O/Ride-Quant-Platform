# ADR-013: Strategy Definition Version — Independent Evidence Axis

## 1. Context

[ADR-010 §75](./ADR-010.md) (Approved) đã khóa Decision computation evidence phải pin **"strategy/model version"** như một field riêng biệt với "code/build version" — nhưng không ADR-010 lẫn [Chapter 9](../constitution/09-plugin-model.md) (Locked) định nghĩa cấu trúc field đó là gì hay quan hệ của nó với Plugin Version (Ch9 §9.1). Để mở, một implementer có thể gộp "strategy/model version" vào Plugin Version — điều này mâu thuẫn trực tiếp với quan hệ M:N mà Ch9 §9.3 đã Locked giữa Plugin Version và Strategy Definition (một Plugin Version có thể phục vụ nhiều Strategy Instance/Definition, và một Strategy Definition có thể có nhiều Plugin Version song song — authoritative/shadow/experimental/migration), và sẽ làm strategy identity churn sai mỗi khi code được refactor mà không đổi nghiệp vụ. Quyết định này chặn việc hoàn thiện Package 0.2-C (Strategy Definition, Strategy Instance, Decision Domain Contract).

## 2. Decision

Product Owner quyết:

> Strategy Definition Version là một trục evidence bất biến, độc lập với Plugin Version, Configuration Version và Package/Build Artifact. Strategy Definition Version sở hữu business và decision semantics. Plugin Version sở hữu implementation-release identity. Không trục nào được làm proxy cho trục kia.

### 2.1 Bốn trục độc lập

| Trục | Sở hữu | Authority |
|---|---|---|
| **Strategy Definition Version** | Business/decision semantics — thesis, decision rules, required inputs, explanation contract, supported capability/instrument-class | Domain Contract (mới, thuộc ADR này) |
| **Plugin Version** | Implementation-release identity | [Chapter 9 §9.1](../constitution/09-plugin-model.md) (Locked) — không đổi |
| **Configuration Version** | Exact parameter values cho một instance cụ thể | [Chapter 9 §9.1](../constitution/09-plugin-model.md) (Locked) — không đổi |
| **Package/Build Artifact** | Exact executable/deployable artifact identity | [Chapter 9 §9.1](../constitution/09-plugin-model.md) (Locked) — không đổi |
| Strategy Instance | Runtime binding — pin cả 4 trục trên | [Chapter 9 §9.3](../constitution/09-plugin-model.md) (Locked) — không đổi, chỉ mở rộng field pin bắt buộc |

Mỗi trục **bump độc lập**: thay đổi thesis/decision-rule không bắt buộc bump Plugin Version; refactor/bugfix không bắt buộc bump Strategy Definition Version — cùng nguyên tắc "ba trục version độc lập, cấm dùng trục này làm proxy cho trục kia" mà [Chapter 10 §10.3](../constitution/10-compatibility-capability-contract.md) (Locked) đã khóa cho Event Contract/`schema_version`/Plugin Version.

### 2.2 Phạm vi Strategy Definition Version — capability/instrument-class, không phải instrument cụ thể

**Strategy Definition Version sở hữu supported capability/instrument-**class** semantics** (ví dụ: "trend-following trên crypto major liquid pairs"). **Lựa chọn instrument cụ thể** (ví dụ: chọn đúng BTCUSDT thay vì ETHUSDT trong lớp đó) **thuộc về Configuration Version hoặc Strategy Instance**, không thuộc Definition.

**Hệ quả bắt buộc:** đổi runtime binding từ một instrument tương thích này sang một instrument tương thích khác trong cùng class **không** bắt buộc tạo Strategy Definition Version mới — đây là thay đổi ở tầng Configuration/Instance. Ngược lại, thay đổi **supported scope** (ví dụ mở rộng từ "crypto major" sang "toàn bộ altcoin"), **decision rules**, **required inputs**, hoặc **explanation contract** **bắt buộc** tạo Strategy Definition Version mới, bất kể Plugin Version có đổi hay không.

### 2.3 Immutable pin, cấm mutable "latest"

Historical Decision evidence phải resolve **exact immutable reference** tới Strategy Definition Version đã dùng tại thời điểm tính — cùng exact-pin pattern mà [Chapter 9 §9.1](../constitution/09-plugin-model.md) đã khóa cho Plugin Version + exact Package/Build Artifact. **Cấm** mọi tham chiếu dạng mutable "latest"/"current definition" — vi phạm sẽ khiến một thay đổi tương lai âm thầm diễn giải lại ý nghĩa của một Decision đã tính (I-3, Ch8 §8.1.1).

### 2.4 Strategy Instance — pin đủ bốn trục

`strategy-instance.md` (Package 0.2-C) phải mở rộng yêu cầu pin của [Chapter 9 §9.3](../constitution/09-plugin-model.md) thành: Strategy Definition Version + Plugin Version + Configuration Version + resolvable Package/Build Artifact — cùng lúc, không thiếu trục nào.

## 3. Alternatives considered

| Phương án | Lý do loại |
|---|---|
| **Plugin Version làm proxy cho strategy semantics** | Ch9 §9.3 đã Locked quan hệ M:N (một plugin phục vụ nhiều strategy, một strategy có nhiều Plugin Version song song) — Plugin Version không thể định danh duy nhất nghiệp vụ strategy. |
| **Configuration Version làm proxy cho definition semantics** | Configuration Version (Ch9 §9.1) là per-instance parameter tuning; hai instance cùng definition nhưng khác tham số sẽ trông như khác "definition" nếu gộp — sai, vì thesis không đổi theo tham số. |
| **Một trục version hợp nhất** | Tái tạo đúng anti-pattern mà [Chapter 10 §10.3](../constitution/10-compatibility-capability-contract.md) đã cấm cho Event Contract/`schema_version`/Plugin Version; phá khả năng phân biệt "code đổi" với "nghiệp vụ đổi" với "tham số đổi" — mất chính xác mà I-1 cần. |
| **Strategy Definition mutable, không có version bất biến** | Vi phạm trực tiếp [I-3](../constitution/02-platform-invariants.md) và [Chapter 8 §8.1.1](../constitution/08-event-model.md) (Referenced Authoritative Artifact phải immutable sau khi được tham chiếu) — một Strategy Definition "hiện tại" mutable sẽ diễn giải lại ngầm mọi Decision lịch sử đã dùng nó. |

## 6. Consequences

**Tích cực:** refactor/bugfix không còn làm churn sai lịch sử strategy identity; một Plugin Version phục vụ nhiều strategy không còn gây va chạm semantic; I-1 evidence đầy đủ hơn — "nghĩa là gì" và "chạy bằng code nào" trả lời được độc lập; I-2 được củng cố vì cả 4 mode phải pin cùng 4 trục.

**Tiêu cực:** thêm một trục version phải pin/theo dõi ở mọi evidence liên quan Decision; đòi hỏi kỷ luật tác giả khi phân loại thay đổi thuộc trục nào (giảm thiểu bằng rule §2.2).

**Thuộc Domain Contract, KHÔNG thuộc ADR này:** schema/versioning scheme cụ thể (SemVer, monotonic, content-hash) của Strategy Definition Version; nội dung thực tế của từng Strategy Definition.

**Ràng buộc lên implementation tương lai:** `strategy-definition.md`, `strategy-instance.md`, `decision.md` (Package 0.2-C) phải khai báo Strategy Definition Version là field bắt buộc, tách biệt khỏi ba trục kia; Event Contract của Decision (khi được author ở Chapter 8 layer) phải mang đủ 4 trục theo yêu cầu ADR-010 §75.
