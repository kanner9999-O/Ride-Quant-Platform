## 1. Context

## 2. Decision question

Ride Quant Platform có nên establish MỘT governed cross-module Error Handling Convention baseline bắt buộc cho implementation module, hay để mỗi module/ngôn ngữ tự quyết định riêng?

## 4. Alternatives considered

- **MỘT governed cross-module baseline (chọn):** error handling nhất quán xuyên module, dễ vận hành/debug cross-module (biết chắc technical error được propagate/translate NHƯ THẾ NÀO xuyên boundary), dễ enforce tooling sau này, giảm drift, hỗ trợ I-1 Explainability (phân biệt rõ technical error khỏi domain outcome) — đánh đổi: autonomy per-module thấp hơn, blast radius rộng hơn nếu chọn sai convention.
- **Error handling convention độc lập mỗi module:** tối đa autonomy per-module — loại bỏ: KHÔNG lý do domain nào yêu cầu 26 module_id (`module-registry.yaml`) xử lý technical error khác nhau về nguyên tắc; error handling không nhất quán làm vận hành/debug/cross-module diagnostics khó hơn không cần thiết, đặc biệt khi một technical error propagate qua nhiều module boundary (vd Execution Engine → Exchange Adapter → Custody/Signing Service, `ADR-017`).
- **Chỉ convention theo ngôn ngữ, KHÔNG platform-level baseline:** nhóm theo Python/Go (ADR-008 layer) — loại bỏ: vẫn thiếu MỘT authority platform-level dưới đó future cross-module semantic Error Handling requirement (định nghĩa chi tiết tại `error-handling.md` tương lai, KHÔNG tại ADR này) CÓ THỂ được thiết lập nhất quán (vd cách một Go `error` propagate qua boundary tới một module Python, VÀ ngược lại) — tách theo ngôn ngữ tạo hai bộ rule độc lập, trùng lặp effort, cùng lesson đã ghi tại `ADR-027`/`ADR-028` §4.

## 5. Consequences

**Benefits:** error handling nhất quán xuyên mọi module; vận hành/audit/debug dễ hơn khi một technical error propagate qua nhiều module boundary; dễ enforce tooling khi triển khai; giảm drift; hỗ trợ I-1 Explainability (technical error tách bạch khỏi domain/business outcome, tránh nhầm lẫn "lỗi hệ thống" với "quyết định business hợp lệ nhưng bị reject").

**Costs/tradeoffs:** error-handling autonomy cấp module thấp hơn; blast radius platform-wide nếu một rule tệ áp dụng nhầm; căng giữa Python/Go idiom (exception vs error-value) và baseline chung; semantic baseline change tương lai CÓ THỂ tự trigger ADR review mới (§3); PHẢI giữ ADR text hẹp trong khi `error-handling.md` tương lai tiếp tục evolve — cùng risk đã ghi tại `ADR-025`/`ADR-026`/`ADR-027`/`ADR-028` §5.
