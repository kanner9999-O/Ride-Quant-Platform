# ADR-036: Genesis Stream Registry Topology — Phase-3 Core Analytical Chain Writer Authority

**Context:** [Chapter 8](../constitution/08-event-model.md) §8.3.1 requires every authoritative event to belong to exactly one ordered stream, and vests stream identity/topology/writer authority/lifecycle/sequence policy/genesis position **solely** in `docs/architecture/stream-registry.yaml` — "KHÔNG có version namespace riêng cho từng stream," Event Contract may only declare eligibility (`allowed_streams`), never define stream existence. [ADR-009](./ADR-009.md) (Approved) §2.6 requires the Genesis Registry to define "đúng MỘT canonical Lifecycle Stream và đúng MỘT canonical Audit Stream," both protected (never retired). No `stream-registry.yaml` exists anywhere in this repository (verified directly, `find` returns nothing). Chapter 8 §8.3.1/§8.5 and ADR-009 §6 explicitly defer the **concrete** topology/writer/genesis mechanics to "Phase 1 design specification" — they decide the *mechanism*, not the *instance*.

**Ground-truth confirmation (direct code inspection, not architecture authority):** the four writer modules of the currently-implemented Phase-3 analytical chain use mutually inconsistent, unauthoritative stream-identity placeholders. `market-data-ingestion` (Go, `internal/publish/memory.go`) uses a single hardcoded `fakeStreamID = "candle-events-fake"`, explicitly commented "placeholder single-stream topology." `structure-engine` (Python) is internally inconsistent with itself: `swing.py` defaults `stream_id: str = "swing"` (flat, module-level) while `structure.py`'s own `_structure_stream_id()` instead derives `f"structure:{structure_subject_id}"` (subject-scoped) — two different partitioning models inside one module, neither pinned by any authority. `raw-regime-engine` defaults `stream_id: str = "regime"` (flat). `feature-engine` defaults `stream_id: str = "feature"` (flat) for both its Regime-passthrough and Swing-distance paths. All of these are constructor-default, caller-overridable Python/Go values — not fixed identities, not registered anywhere, not resolvable under [Chapter 8 §8.1.1](../constitution/08-event-model.md)'s five conditions for a Referenced Authoritative Artifact (versioned; immutable-once-referenced; non-reused identifier; persistently resolvable; verifiable content identity). This is exactly the gap [ADR-035](./ADR-035.md) (Approved) already relies on existing and already refuses to paper over with an invented stand-in for Feature's own `computation_cursor.input_contract_ref`/`stream_registry_version`/`lifecycle_frontier`/`stream_positions` — that ADR's fail-closed posture is only as good as this genuinely-unresolved prerequisite being resolved by real architecture, not by any single module quietly picking its own convention.

**Scope classification — `ADR Required`, independently triggered.** This ADR is **not** justified by "`P3-FEATURE-A-MAJ-06` needs another ADR" — it is triggered because establishing which concrete non-protected streams exist and which module holds sole writer authority over each is, per [Chapter 8 §4b](../constitution/00-governance.md) and Chapter 8 §8.3.1's own text ("Tạo/xóa/tách stream, hoặc đổi writer authority, là thay đổi Event Model → ADR Required"), a genuine Event-Model change: it affects four already-registered modules simultaneously (`>1 module`) and is hard to reverse once event data accumulates under a given topology (changing stream boundaries later requires a new ADR plus a registry-version transition affecting every consumer's `stream_positions`/`lifecycle_frontier` bookkeeping). No already-Approved authority pins the concrete stream identities/topology/writers needed here — Chapter 8/ADR-009 explicitly defer this to Phase 1 design work, and no such design has been authored. `ADR_REQUIRED` confirmed by direct inspection, not assumption.

**Decision:** Establish the minimum Genesis Registry topology for the currently-implemented analytical chain (`Market Data Ingestion → Structure/Swing → Raw Regime → Feature`) as **one logical stream per authoritative fact family a writer module owns**, never scoped/partitioned by instrument/venue/timeframe/strategy:

```text
Stream                          Writer authority (module_id, module-registry.yaml)   Carries
market-data-ingestion-candle    market-data-ingestion                                 entire Candle event family
                                                                                       (CandleObserved/CandleClosed/
                                                                                       CandleCorrected/CandleDataGapObserved)
structure-engine-swing          structure-engine                                      Swing event family
                                                                                       (SwingCandidateDetected/
                                                                                       SwingConfirmed/SwingInvalidated)
structure-engine-structure      structure-engine                                      Structure event family
                                                                                       (BreakOfStructureDetected/
                                                                                       ChangeOfCharacterDetected/
                                                                                       StructureFactInvalidated/
                                                                                       StructureRecomputed)
raw-regime-engine-regime        raw-regime-engine                                     Regime event family
                                                                                       (RegimeClassified/
                                                                                       RegimeFactInvalidated)
feature-engine-feature          feature-engine                                        Feature event family
                                                                                       (FeatureComputed/
                                                                                       FeatureFactInvalidated)
```

**1. Partitioning rule (item 1/3):** exactly one stream per writer module per authoritative fact family it owns — `structure-engine` owns two streams (Swing, Structure) because they are two distinct Domain Contracts (`swing.md`/`structure.md`) with different consumer sets (Feature consumes only Swing, per `feature.md` §14's exclusion list; a future Context module would consume Structure) — keeping them separate lets a future Feature-scoped Input Contract include exactly the Swing stream without needing to filter Structure events out of a shared stream. No stream is partitioned by `instrument_id`/`venue_id`/`timeframe`/`strategy` — see Alternative 2 for why.

**2/8. Writer authority and protected streams (items 2, 8):** each stream above has **exactly one** writer authority, the module already registered in `module-registry.yaml` as sole authoritative owner of that fact family (Chapter 3 §3.1) — this introduces no new writer-coordination mechanism, it simply names the writer each module already is. Two additional streams are **inherited, not redecided** here: the ADR-009-mandated canonical Lifecycle Stream and canonical Audit Stream, both protected (never retired, per Chapter 8 §8.3.5/ADR-009 §2.6, unchanged). Chapter 8's own worked examples (§8.3.1, §8.4, §8.5) consistently illustrate the Lifecycle Stream as `stream_id: platform-lifecycle` — **this is Chapter 8's own recurring illustrative convention, not an explicitly Locked mandatory string**; no sentence in Chapter 8 or ADR-009 states the literal name is fixed. This ADR **recommends** adopting `platform-lifecycle` verbatim for direct consistency with every existing Constitution example (avoiding an invented divergent name with zero benefit), and proposes `platform-audit` for the canonical Audit Stream (Chapter 8 gives no existing illustrative name for it). **Writer authority for these two protected streams is explicitly deferred** to the concrete Genesis Registry authoring transaction (Consequences step 4) — it is a platform-bootstrap decision orthogonal to which analytical engines exist, and ADR-009 §6 already defers "registry activation workflow"/bootstrap mechanics to Phase 1 design spec.

**4. Stable/non-reusable identity, genesis position (item 4):** each stream_id above is a Logical Stream Identity (Chapter 8 §8.3.1) — stable across all future `registry_version` transitions, never reused even if retired. All five analytical streams begin at `genesis_position: 0` (Chapter 8 §8.3.1's own registry schema) since they are new streams introduced at the same Genesis Registry with no pre-existing data.

**5. `stream_ref.registry_version` resolution (item 5):** once a concrete Genesis Registry is authored (Consequences step 4) with its own immutable `registry_version` identifier, every future event these five writer modules emit pins that exact value. This repository has **no production authoritative event log today** (Phase 3 development, LIVE `NOT_AUTHORIZED`) — there is no real historical data requiring migration. The `"v0"`/`"swing"`/`"regime"`/`"feature"`/`"candle-events-fake"` placeholders in current code (item 9) are **implementation assumptions, never grandfathered authority**: they must be *replaced* by the genuine Genesis `registry_version` and stream_ids once the concrete registry exists (Consequences step 6), not reinterpreted as already-valid Genesis values.

**6. Boundary vs. Event Contract `allowed_streams` (item 6):** per Chapter 8 §8.3.1's own already-Locked rule ("Stream Registry KHÔNG chứa `allowed_event_types`... khai báo MỘT CHIỀU tại Event Contract"), this ADR pins **only** which module writes to which stream (topology) — it does **not** decide, and the future concrete `stream-registry.yaml` must **not** contain, which event *types* may target each stream. That eligibility is declared exclusively by each event type's own future Event Contract `allowed_streams` field (Domain-Contract-level work, out of this ADR's scope, unauthored for any of the four modules' events today).

**7. No global ordering introduced (item 7):** per-stream sequence remains contiguous, atomically allocated by the single named writer (ADR-009 §2.1, unchanged). No cross-stream sequence comparison and no global ordinal is introduced by this topology — five independent per-stream counters, exactly as ADR-009 §2.3 already requires.

**9. Migration treatment (item 9):** see item 5 above — no data migration exists to perform; code/test stream-identity assumptions are replaced, not migrated, once concrete artifacts exist.

**Scale invariance (directly supports Scale check):** under this topology, growth in instrument/venue/timeframe/strategy count changes **event volume within** the five already-existing streams — it never creates a new stream, never bumps `registry_version`, and never requires a new ADR. A `registry_version` bump is reserved for genuine structural changes (a new writer module, a stream retirement, a writer handoff) — rare, deliberate Event-Model decisions, not routine data growth.

**Alternatives considered:**

1. **One stream per writer module per authoritative fact family (chosen).** Matches each module's already-registered "one authoritative implementation per capability" status (Chapter 3 §3.1) with trivial single-writer satisfaction; keeps the five-stream (seven including protected) topology scale-invariant with respect to instrument/venue/timeframe/strategy growth; cleanly separates Stream Registry topology authority from `subject_ref`/Event-Contract payload-scoping authority (Chapter 8 §8.2.2), which this ADR does not touch.
2. **Scope-partitioned streams (module + instrument/venue/timeframe).** Rejected — would require creating (and registering, per §8.3.1's "creating a stream is an Event-Model change") a new stream for every new instrument/venue/timeframe combination, growing stream count combinatorially rather than the "hàng trăm" total ADR-009 §5 anticipates for the *entire platform*; also conflates Stream Registry topology with `subject_ref` scoping, which Chapter 8 explicitly separates.
3. **One shared analytical stream for all four modules.** Rejected — directly violates Chapter 8 §8.3.1's single-writer-per-stream invariant: four independent writer modules cannot atomically share one contiguous sequence counter without an unauthorized new cross-module coordination component, and would either require inventing one or silently create multiple de facto writers on one stream (an explicit integrity violation, §8.3.2).
4. **Preserving current arbitrary caller-supplied/default stream IDs as authority.** Rejected — these are unauthoritative, mutually inconsistent even within one module (`structure-engine`'s own flat-vs-subject-scoped split), caller-overridable rather than fixed, and never satisfy Chapter 8 §8.1.1's Referenced-Authoritative-Artifact conditions. This is precisely the gap this ADR exists to close, not a valid alternative to closing it.
