# ADR-035: Feature Computation Cursor — Canonical Chapter 8 Replay Cursor as Durable Evidence for Authoritative Feature Facts

> **v0.2 — bounded Review A correction**, addressed/remediated pending re-review (not self-closed by the correction executor — closure is a Review A re-review determination, never asserted here): `P3-ADR035-A-MAJ-01` (v0.1 defined a second, Feature-local, near-Replay-Cursor schema instead of reusing Chapter 5/8's own already-owned Replay Cursor mechanics — corrected: `computation_cursor`'s value is now the canonical Chapter 8 §8.5 Replay Cursor verbatim, with all five required fields, selected via a Feature-scoped Input Contract instance rather than `feature_definition_version`/§14's closed contract-ID vocabulary, which was never a stream-identifying artifact; the unsupported fixed "1–2 stream" cardinality claim is removed), `P3-ADR035-A-MAJ-02` (v0.1 defined visibility as a `recorded_time`-only inequality — corrected: visibility now requires the full three-part predicate — stream-universe membership, in-stream sequence position, and recorded-time boundary — with no cross-stream sequence comparison, applied explicitly to `R_original`/`R_later` and ADR-034's conditions (a)/(b); this refines proof mechanics under Chapter 5/8 authority and does NOT alter ADR-034's causal-supersession decision itself), `P3-ADR035-A-MIN-01` (v0.1 falsely attributed the local-artifact-minimality rationale to "ADR-034 Alternative 2's identical rejection logic" — ADR-034's actual Alternative 2 rejected suppressing the B → A(N+1) invalidation/replacement, an unrelated decision; corrected to state the minimality rationale on its own footing, with no false historical citation). **No change to**: `ADR_REQUIRED` classification, required durable cursor evidence on `FeatureComputed`/`FeatureFactInvalidated`, per-fact original/replacement cursor independence, append-only semantics, the history-preserving implementation consequence, the no-global-total-order constraint, or `P3-FEATURE-A-MAJ-04`/`P3-FEATURE-A-MAJ-06` remaining `OPEN`.

**Context:** [ADR-034](./ADR-034.md) (Approved) authorizes `FeatureFactInvalidated.invalidation_cause: eligible_swing_selection_superseded`, but pins it fail-closed: the cause is semantically defined yet **operationally NOT EMITTABLE** until `R_original` — the computation cursor `R` under which the invalidated `FeatureComputed` originally evaluated [`feature.md`](../domain/feature.md) §9a's Eligible-Swing eligibility — can be proven from **durable, replay-reconstructable authoritative evidence**, surviving process restart and reconstructable identically by every execution mode (Live/Backtest/Paper Trading/Replay, §13). ADR-034 explicitly forbids substituting `FeatureComputed.recorded_time` or any process-local/in-memory tracking for `R_original`. No field or artifact in current authoritative Feature event schema durably records `R`. This is `P3-FEATURE-A-MAJ-06`'s architecture prerequisite.

**Ground-truth confirmation (direct code inspection, `swing_distance.py`, commit `07eb8ecf475cdb6ab6ef7ac6f63283520c99111a`):** the engine already takes an explicit `cursor` keyword argument on `on_candle`/`on_swing_confirmed`/`on_swing_invalidated` — but this alone does not satisfy the durability requirement. `FeatureComputed` (`contracts.py`) has no cursor field at all. Redelivery of an identical `EventRecordRef` on `on_candle` short-circuits to `return []` (dedup, feature.md §3 rule) before any as-of computation runs, so the same stored Candle cannot be re-evaluated under a different cursor through that path. `_SwingState` retains only the current revision, and `on_swing_invalidated` destructively sets `state.invalidated = True` in place — later-ingested Swing knowledge overwrites the exact state an earlier-cursor evaluation would need to reconstruct. The explicit `cursor` parameter is necessary but not sufficient: it changes *how eligibility is computed at call time*, not *what is durably provable afterward*.

**Scope classification — `ADR Required`.** Same Chapter 0 §4b "Event Schema" trigger as ADR-034, independently sufficient per the disjunctive reading ADR-034 established (citing [ADR-025](./ADR-025.md)). A durable cursor requires adding required payload structure to `FeatureComputed`/`FeatureFactInvalidated` — a schema change to authoritative Feature events, not a mechanism-only/implementation-detail choice. No existing higher-authority mechanism resolves this without an Event-Schema change: `recorded_time` is a distinct axis (append time, not evaluation-boundary time — [Chapter 5](../constitution/05-time-model.md) §5.1/§5.4, and the exact substitution ADR-034 already forbids); `input_fact_refs`/`causation_refs` record only facts that *were* selected, never the boundary that determined what was visible-but-rejected (the winning-later `SwingConfirmed` that triggers the new cause is, by construction, absent from the original fact's `input_fact_refs`); and no in-memory/process-local value can be durable by definition. This ADR does not relitigate ADR-034's own classification, and confirms — after direct inspection, not assumption — that no non-schema-changing option closes this specific gap.

**Decision:** Feature's authoritative `FeatureComputed` and `FeatureFactInvalidated` events (`feature.md` §3/§4) each carry one new **required** payload field, `computation_cursor`. Its **value is a canonical [Chapter 8](../constitution/08-event-model.md) §8.5 Replay Cursor, verbatim** — not a second, Feature-local, near-equivalent schema. `feature.md` §18 already commits Feature to "áp dụng, không định nghĩa lại... ordering/replay cursor mechanics (Chapter 5/Chapter 8)"; a locally-invented cursor shape would violate that authority boundary Feature itself already pins. Chapter 8 §8.4 sets the exact precedent for reuse: `decision_context_cursor` "LÀ một Replay Cursor hợp lệ... dùng CÙNG canonical schema §8.5, không phải một schema gần giống nhưng khác field." This decision applies that identical precedent to Feature's own payload-scoped cursor field.

```yaml
computation_cursor:                       # value type = canonical replay_cursor, §8.5.1
  recorded_time:                          # Required — knowledge boundary
  input_contract_ref:                     # Required — {contract_id, contract_version},
                                           #   the Feature-scoped Input Contract instance
                                           #   this computation pinned (Chapter 8 §8.3.4)
  stream_registry_version:                # Required — must match input_contract_ref's
                                           #   pinned registry version (§8.5)
  lifecycle_frontier:                     # Required — {stream_id, position: {kind, sequence}}
                                           #   on the canonical Lifecycle Stream (§8.3.5)
  stream_positions:                       # Required — map <stream_id> -> <sequence>,
                                           #   cardinality = exactly included_streams of the
                                           #   pinned Input Contract, valid at lifecycle_frontier
                                           #   — never a fixed count, never open-ended, never a
                                           #   cross-stream sequence (ADR-009's no-global-order)
```

**Feature Definition vs Input Contract — two distinct artifacts, not conflatable.** `feature_definition_version` (`feature.md` §6) pins *computation semantics* (formula, thresholds, policy identifiers) — it is not, and was never designed as, a stream-scope artifact. `feature.md` §14's six-entry closed contract-ID enumeration lists which **Event Contracts** a `feature_type` may consume — it names contract IDs, not stream instances, and does not resolve to a `stream_positions` universe. Selecting the exact upstream **stream** universe a given computation pinned is Input Contract's job (Chapter 8 §8.3.4: "Input Contract sở hữu duy nhất final merge policy... included_streams... frontier_policy"). This decision therefore requires a Feature-scoped Input Contract instance to exist and be pinned by `input_contract_ref` — its concrete content (`included_streams`, `merge_policy`, `frontier_policy`) is deferred to the follow-on implementation work, same deferral status already used throughout `candle.md`/`swing.md`/`structure.md`/`regime.md`/`feature.md` for `stream_ref.registry_version`/`producer_ref` (Phase 1, not yet authored).

**Fail-closed consequence — explicitly stated, not glossed over.** `docs/architecture/stream-registry.yaml` and any Feature-scoped Input Contract do not yet exist as persistently resolvable artifacts (§8.1.1) in this repository. Until they do, a `computation_cursor` value cannot genuinely satisfy §8.1.1's five conditions (versioned; immutable-once-referenced; non-reused identifier; persistently resolvable; verifiable content identity) — it is schema-populated but not yet **proof**. This ADR does not amend Chapter 8 to relax that requirement, and does not invent a bounded stand-in that would satisfy it artificially. Concretely: `computation_cursor`'s **schema** is authorized now (this ADR, followed by the `feature.md` amendment); but no Feature event may **claim** `computation_cursor` as durable evidence satisfying ADR-034's fail-closed prerequisite for `eligible_swing_selection_superseded` until the referenced Stream Registry/Input Contract artifacts are genuinely persistently resolvable. This is the same fail-closed posture ADR-034 already established for the invalidation cause itself, now extended to the specific artifacts its evidence depends on.

**Full cursor visibility — position participates, not `recorded_time` alone (`P3-ADR035-A-MAJ-02`).** [Chapter 5](../constitution/05-time-model.md) §5.3's recorded-time inequality is **necessary but not sufficient** whenever an ordering position is needed to disambiguate the boundary (§5.3: "Timestamp một mình không đủ khi nhiều event cùng recorded_time"). An upstream event `E` is visible at computation cursor `R` **if and only if all three hold**:

```text
1. E.stream_id is in R's valid stream universe — i.e. E.stream_id ∈
   R.input_contract_ref's included_streams, and that stream's inclusion is valid at
   R.lifecycle_frontier (Chapter 8 §8.3.5 Retained-in-Universe semantics — a retired
   stream stays in-universe up to its terminal_position, not silently excluded);
2. E.sequence <= R.stream_positions[E.stream_id] — an IN-STREAM position boundary only;
   NO cross-stream sequence comparison is ever performed (Chapter 8 §8.3.3);
3. E.recorded_time <= R.recorded_time (Chapter 5 §5.3's recorded-time boundary).
```

Any one condition failing makes `E` not visible at `R`. This predicate applies directly to `R_original`/`R_later` and to ADR-034's conditions (a)/(b) — condition (a) ("winning `SwingConfirmed` was NOT visible at `R_original`") means the predicate fails on at least one of the three legs against `R_original`; condition (b) means all three hold against `R_later`. **This refines the proof mechanics under Chapter 5/8's own authority — it does not alter ADR-034's causal-supersession decision, its four conditions, `causation_refs` binding, or mutual exclusion with `swing_invalidated`, any of which remain exactly as Approved.**

**Where it applies and how `R_original`/`R_later` are recovered:**

- `computation_cursor` is required on **every** `FeatureComputed` — original and replacement alike (§3's "no shortcut" and correction-lineage invariants are unaffected; each computation event, original or replacement, pins the exact `R` under which *it* evaluated eligibility). `R_original` for an invalidated fact is read directly off that fact's own `computation_cursor` — no external state, no process memory.
- `computation_cursor` is required on **every** `FeatureFactInvalidated`, pinning the `R_later` under which the re-evaluation that produced *this* invalidation was performed — this is exactly the evidence ADR-034's conditions (a)/(b) need to prove a winning `SwingConfirmed` was invisible at `R_original` and visible at `R_later`, evaluated against the full visibility predicate above.
- This makes `computation_cursor` universal across all three founding feature types (`feature.md` §12 already states recorded-time visibility, condition (a), applies to *every* Feature input, not only `distance_to_last_confirmed_swing`) — the field is not scoped narrowly to the one feature type ADR-034's new cause targets, since the underlying evaluation-boundary concept it records is already universal in the Domain Contract.

**Relationship to other time/ordering axes — no field is redefined; relational invariants are inherited directly from [Chapter 8](../constitution/08-event-model.md) §8.5.2, not merely "modeled on" it:**

```text
computation_cursor.recorded_time  ≠  envelope.recorded_time (append time, unaffected)
computation_cursor.recorded_time  ≠  effective_time / effective_window (§12, unaffected)
computation_cursor.recorded_time  ≠  any single upstream event's own recorded_time
                                      (the exact substitution ADR-034 already forbids)

Cursor → Fact (= Chapter 8 §8.5.2's "Cursor → Decision", applied verbatim):
  computation_cursor.recorded_time <= FeatureComputed.recorded_time
  computation_cursor.recorded_time <= FeatureFactInvalidated.recorded_time

Position → Cursor (= Chapter 8 §8.5.2's "Position → Cursor", applied verbatim,
anti-look-ahead):
  every event referenced by stream_positions must have
  recorded_time <= computation_cursor.recorded_time — a cursor entry pointing to an
  event from the future relative to its own recorded_time boundary is invalid and
  must be rejected at append.

Lifecycle → Cursor (= Chapter 8 §8.5.2's "Lifecycle → Cursor", applied verbatim):
  lifecycle_event.recorded_time <= computation_cursor.recorded_time

feature.md §9a step 2 / §12's existing eligibility test is restated using the full
visibility predicate above, not a recorded_time-only rule:
  SwingConfirmed visible at computation_cursor  <=>  all three legs of the predicate hold
```

**Implementation consequence (architecture requirement, not a mandated data structure):** an implementation satisfying this ADR must be able to reproduce, for any `computation_cursor` value appearing on a durable authoritative Feature event, the correct as-of eligibility answer (per the full visibility predicate above) for the upstream fact(s) that cursor governs — i.e. engine-internal upstream state must be **cursor-aware and history-preserving**, not single-current-revision. Ingesting a later Swing revision or invalidation must never destroy the ability to correctly answer an earlier-cursor query. The two ground-truth symptoms above (identical-ref dedup short-circuiting recomputation; destructive single-revision Swing state mutation) are concrete instances of this gap and must be resolved by the follow-on implementation remediation — but the *specific* internal representation (revision history list, event-sourced replay, or another mechanism) is implementation-level and is deliberately **not** dictated here.

**Append-only/determinism preserved:** `computation_cursor` is populated once, at construction, exactly like every other payload field (I-3 append-only, unaffected); no existing field is mutated; a replacement fact's `computation_cursor` is independent of the fact it supersedes, reflecting that specific replacement's own re-evaluation boundary.

**Alternatives considered:**

1. **`computation_cursor`'s value is the canonical Chapter 8 §8.5 Replay Cursor, selected via a Feature-scoped Input Contract instance (chosen).** Reuses already-Locked, already-owned mechanics exactly per Chapter 8 §8.4's own reuse precedent; adds zero new time/ordering concept; keeps `feature.md` §18's "áp dụng, không định nghĩa lại" boundary intact.
2. **A second, Feature-local, bounded cursor schema, deliberately distinct from Chapter 8's canonical `replay_cursor` (this ADR's own v0.1 decision).** Rejected on Review A correction (`P3-ADR035-A-MAJ-01`) — Chapter 5/Chapter 8 already own Replay Cursor mechanics in full; a parallel near-equivalent schema recreates the identical concept under a second, competing authority, directly contradicting `feature.md` §18's explicit "ordering/replay cursor mechanics" deferral to Chapter 5/8 and I-12's one-concept-one-authoritative-source discipline.
3. **A separate authoritative cursor/provenance artifact referenced by Feature events (a new event type, Event Contract, and stream).** Rejected on its own footing — adds an entire new authoritative-artifact class, causation hop, and stream/registry surface area for information that fits directly on the fact that already needs it, with no correctness benefit; Chapter 8 §8.4 made the identical choice for Decision (embed `decision_context_cursor` directly rather than a separate referenced event). *(Note: this is not the same rejection ADR-034's own Alternative 2 made — that alternative rejected suppressing the B → A(N+1) invalidation/replacement, an unrelated decision; no such citation is made here.)*
4. **Deriving the cursor from existing envelope/evidence fields (`recorded_time`, `input_fact_refs`, `causation_refs`).** Rejected — `recorded_time` is append time, not evaluation-boundary time (the exact substitution ADR-034 forbids); `input_fact_refs`/`causation_refs` record only facts that *were* selected, never the boundary that determined what was visible-but-rejected, so they cannot answer the visibility question for a `SwingConfirmed` absent from those refs — precisely the case `eligible_swing_selection_superseded` needs to prove.
5. **Overloading `correlation_id` or `invalidation_reason`.** Rejected — `correlation_id` already has a distinct, Locked Chapter 8 §8.2.1 semantic (workflow-correlation, not knowledge-boundary); `invalidation_reason` is optional, free-text, and not machine-validated (`feature.md` §4 payload). Conflating either with cursor evidence violates I-12/Chapter 6's one-concept-one-field discipline — the same reasoning Chapter 8 §8.4 gives for why `decision_context_cursor` needed its own field rather than reusing `decision_time`.
6. **Relying on process-local/in-memory engine state alone.** Rejected — explicitly the exact gap ADR-034 already closed the loophole on; not durable, not restart-survivable, not independently reconstructable by a second process or a different execution mode.
7. **A new global cross-stream sequence/order.** Rejected — would contradict [ADR-009](./ADR-009.md)'s decision that no global total order exists across independent streams; `stream_positions` stays a per-stream map with no cross-stream sequence comparison (visibility predicate leg 2 above), never a cross-stream ordinal.

**Consequences:** This ADR resolves the durable-cursor **architecture prerequisite** only. It does not itself amend `feature.md`, does not implement `feature-engine`, does not remediate `swing_distance.py`, and does not close `P3-FEATURE-A-MAJ-04` or `P3-FEATURE-A-MAJ-06`. Three bounded, separate, ordered follow-on transactions are required: (1) a versioned `feature.md` amendment adding `computation_cursor` to `FeatureComputed`/`FeatureFactInvalidated` §3/§4 payload with the invariants above, **and aligning §9a step 2 / §12's cursor-visibility text with the full three-leg visibility predicate defined here** (replacing the current recorded-time-only phrasing with the stream-universe-membership + in-stream-position + recorded-time predicate) — Review A/B on that Domain Contract delta; (2) a bounded `feature-engine` implementation remediation making engine-internal upstream state cursor-aware/history-preserving, authoring/pinning a Feature-scoped Input Contract instance, and populating `computation_cursor` on every emitted fact once the referenced Stream Registry/Input Contract artifacts are genuinely persistently resolvable (§Decision "fail-closed consequence") — which then satisfies ADR-034's evidence prerequisite and unblocks `eligible_swing_selection_superseded` emission, with accompanying tests proving the exact `A -> invalidate -> B(temporary) -> A(N+1)-wins` scenario now durably provable across a simulated restart; (3) a bounded Review-A re-review of `P3-FEATURE-A-MAJ-04`/`P3-FEATURE-A-MAJ-06` against the corrected representation. This ADR does not change ADR-034's decision, its new invalidation cause, Eligible-Swing ordering's underlying total order (`feature.md` §9a), Feature subject identity (§1), Feature-to-Feature dependency (§10, still deferred), the module dependency graph, or any ownership boundary — Structure/Raw-Regime/Context/Strategy ownership, `module-registry.yaml`, and Chapter 8 (Locked) are all unaffected and unreferenced by this decision.
